# 02 · 使用说明书

> 适用版本：**AI本地错题习题归档整理工具 v1.0.0**
> 面向对象：第一次打开这个软件的同学（会点鼠标就行，不需要懂编程）
> 配套文档：[`01-安装部署教程.md`](01-安装部署教程.md)（还没装好先看它）、[`03-常见问题排查.md`](03-常见问题排查.md)（出问题看它）
>
> 一句话概括：**把手机/扫描仪拍的一堆习题照片，自动变成「一道一道可搜索、可统计、可打印的错题」，
> 顺手给每道错题写一份分析报告，并按「学科 / 学段 / 题型 / 状态」自动归档成文件夹。**

## 2. 五分钟上手：导入 → 识别 → 看结果 → 出报告 → 导出
**第 0 步：启动。** 双击项目根目录的 `启动.bat`。双击没反应或报错，改用 `启动-控制台.bat`（错误信息会留在窗口里）；
想确认环境是否正常，双击 `环境自检.bat`。

**第 1 步：导入图片。** 点 `📂 导入文件夹`，选一个装着习题照片的文件夹（比如手机导出的 `照片/2025-错题`）。
导入后左栏「待识别图片」列出每张图，「质量」列此时显示分辨率（如 `1600×1200`）。
图片会被复制一份到 `data/images/导入_年月日_时分秒/`，所以之后你删手机里的照片也不影响软件。

**第 2 步：开始识别。** 点 `▶ 开始识别`。每张图会走：自动预处理（纠偏/提亮/锐化）→ 本地模型识别 →
必要时云端复核 → 入库 → 自动归档 → 错题自动生成报告。看三处就知道进度：状态栏进度条、
左栏「状态」列由 `待识别` 变 `已识别`、「题数」列出现题目数、「质量」列变成质量分（如 `0.86`）。

**第 3 步：看结果。** 中间「识别与归档」页右边就是「识别结果」：上面一小张列表（题号/题型/状态/置信度），
点一行，下面表单显示这道题的全部字段。**置信度低（比如 0.4）的那几行重点看**，对照左边预览图检查有没有识别错。

**第 4 步：出报告。** 到「题库」页签选一道错题 → 中间自动切到「错题分析」页 →
点 `🧠 生成/更新分析（本地模型）`，几十秒后拿到六段式报告。
（其实第 2 步识别出错题时已经自动生成过一份，这一步是"再生成一份更好的"。）

**第 5 步：导出。** 点 `⬇ 导出 ▾ → 导出全部错题（个人错题本）…`，默认文件名 `个人错题本_年月日.docx`。
想打印选 `.pdf`，想在手机上看选 `.html`，想自己改内容选 `.docx`。

跑完这五步，你已经有：① 一个能搜能统计的本地题库；② 一堆按学科分好的归档文件夹；③ 一份能直接打印的错题本。

## 3. 逐区详解
### 3.1 上传区（左栏「待识别图片」）
| 列 | 含义 |
| --- | --- |
| 图片 | 文件名（导入时复制过来的那份） |
| 状态 | `待识别` → 识别后 `已识别`；识别不出题目会显示 `失败` |
| 题数 | 这张图里识别出几道题 |
| 质量 | 导入时是分辨率；识别后是质量分（0~1，越高越清楚） |

列表下面三个按钮：`载入编辑器`（把选中的图送进「图片预处理」页并切过去）、
`本地重识别`（强制只用本地模型重识别这一张）、`云端重识别`（强制走云端，需云端增强已开启）。

两个实用操作：**双击**某一行 = 只识别这一张；已经识别过的图再点「开始识别」会**再入库一次**
（生成新题号，出现重复题），所以整批重跑前先用 `🗑 移除选中` 把已识别的挑出去。

### 3.2 预览区（「识别与归档」页左边）
- 大图：显示当前选中的图片（最长边按设置里的 `ui.image_display_max`，默认 1200 像素）
- 图下方说明：文件名、宽×高、文件体积
- `上一张` / `下一张`：在待识别列表里前后翻
- `重新识别本张`：重新识别当前这张（按当前运行模式的正常流程）
- `载入预处理`：把这张图送进「图片预处理」页

### 3.3 识别结果区（「识别与归档」页右边）——识别错了在这里改
上半部分是结果列表：**题号**（这道题在本张图里的序号）、**题型**、**状态**（错题/正确题/未做题）、
**置信度**（模型把握，0~1；低于 0.70 的优先人工核对）。下半部分字段表单，**全部可以手改**：

| 字段 | 填什么 | 备注 |
| --- | --- | --- |
| 学科 | 数学/英语/物理/化学/生物/语文/其他 | 有下拉，也能自己打字 |
| 细分学科 | 如「高等数学」「完形填空」「力学」 | 自由文本，会写进归档与报告 |
| 学段 | 小学/初中/高中/大学/其他 | 有下拉 |
| 题型 | 选择题/填空题/解答题/计算题/判断题/简答题/证明题/作文题/其他 | 有下拉 |
| 状态 | `wrong`=错题、`correct`=正确题、`blank`=未做题 | 下拉是这三个英文代码，**它决定要不要写报告、归到哪个目录** |
| 题干 | 题目正文 | 多行输入框 |
| 选项 | 每行一个（`A. 2`） | 空行会被忽略 |
| 我的答案 | 你卷面上写的答案 | 报告里会拿它和正确答案对比 |
| 我的步骤 | 你写的解题过程 | 写得越全，报告对"错在哪一步"的判断越准 |
| 参考答案 | 标准答案 | 填了它，规则版报告也能给出对照 |
| 知识点 | 多个用**顿号**分隔，如 `导数、函数最值` | 统计看板的"薄弱知识点"靠它 |
| 标签 | 自己起的名，如「2025春季练习册P32」 | 敲回车或点`添加`；标签条上点 `✕` 只是从界面移除 |

表单下面四个按钮：`💾 保存修改`（写回数据库，**并顺手更新归档目录里的文字稿**）、
`🧠 生成错题分析`（给当前这道题生成报告，并自动跳到「错题分析」页）、
`📄 导出本题`（Markdown/Word/PDF/纯文本/网页）、`打开原图`（用系统看图软件打开，优先打开预处理后的工作图）。

> **手动修正识别错误的标准动作：**
> ① 对照预览区的原图 → ② 点中出错的题 → ③ 改字段（**先把「状态」改对**）→ ④ 点 `💾 保存修改` →
> ⑤ 如果状态从"未做题"改成了"错题"，再点 `🧠 生成错题分析`，报告就按新内容生成。
> 保存后 `data/归档/` 里对应题目目录下的 `.md` 文字稿也会同步刷新，不用手动改文件。

### 3.4 错题分析区（「错题分析」页）
顶部显示当前题目（题号 + 状态 + 学科/题型）和**报告来源**（本地规则 / 本地模型 / 云端模型）。四个按钮：

| 按钮 | 作用 | 什么时候用 |
| --- | --- | --- |
| `🧠 生成/更新分析（本地模型）` | 先用本地模型生成；若云端增强已开启、且设置里勾了「错题分析使用云端深度版」，会自动升级为云端深度版 | 日常离线复习，最常用 |
| `☁ 云端深度分析` | 强制尝试云端深度分析（归因更细、变式题更贴合） | 想彻底搞懂某道难题 |
| `📋 复制报告` | 报告全文复制到剪贴板 | 粘到微信问老师、粘进笔记 |
| `📄 导出本报告` | 存成 Markdown / 纯文本 / 网页 | 单独打印某一题的讲解 |

报告正文按六段结构展示，怎么读见第 5 节。

### 3.5 分类归档区（左栏「题库」+「归档目录」）
**「题库」页签**：列出已入库题目，列是 题号/学科/题型/状态/题干（截断 60 字），
状态用颜色区分（错题偏红、正确题偏绿、未做题灰）。上面两个过滤器：
「状态」可筛 空（全部）/ `wrong` / `correct` / `blank`；「学科」可筛 空（全部）/ 数学 / 英语 / 物理 / 化学 / 生物 / 语文 / 其他。
下面两个按钮：`查看/分析`（把选中题载入表单并跳到「错题分析」页）、
`删除选中题`（二次确认；**只删数据库记录，归档目录里的文件要自己清理**）。

> 小贴士：在「题库」里点任意一行，只要当前不在「识别与归档」或「错题分析」页，
> 界面会自动跳到「错题分析」页给你看报告——这是设计好的快捷方式，不是卡住了。

**「归档目录」页签**：一棵目录树 + `刷新目录树` 按钮。为了不卡界面，树最多展开 3 层、
每层最多列 80 个文件夹 / 60 个文件。结构见第 8 节。

### 3.6 搜索区（「全局搜索」页）
搜索框输入关键词，按**回车**或点 `搜索`；右侧显示「共 N 条结果」；结果列是
题号/学科/题型/状态/知识点/题干；选中一条，下方详情区显示题干、选项、我的作答、参考答案、
错题分析摘要和**归档目录路径**。语法与可搜字段见 6.1。

### 3.7 统计看板
六张卡片：**图片总数**、**题目总数**、**错题数**（红）、**正确题**（绿）、**未做题**（灰）、**错题分析报告**。
四张 Canvas 手绘图表（不依赖任何图表库）：
- **各学科题目占比**（饼图）：最近练得最多的是哪科；某科几乎为 0 说明该刷了
- **题型分布**（柱状，最多 8 类）：选择题多还是解答题多，反映练习结构
- **薄弱知识点**（错题次数，红色，最多 8 个）：**最重要的一张图**，反复错的考点排最上面
- **错误原因分布**（最多 8 类）：是"计算失误"多还是"知识点盲区"多，决定该练计算还是回去看课本

### 3.8 运行日志 与「更多 ▾」菜单
日志带 `[时:分:秒]` 前缀，记录模型耗时、tokens/s、云端兜底原因、导出结果等；
底部 `清空显示`（只清界面）、`打开日志文件`（打开 `data/logs/app.log`）。
**遇到异常先看日志最后几条**，通常已写明原因和建议。

| 「更多 ▾」菜单项 | 做了什么 |
| --- | --- |
| 打开数据目录 / 打开归档目录 | 用资源管理器打开 `data/` 或归档根目录（默认 `data/归档`） |
| 查看运行日志文件 | 打开 `data/logs/app.log` |
| 重建归档索引 | 在归档根目录重写 `归档索引.md`（统计 + 各学科题量 + 薄弱知识点） |
| 导出全部数据 (JSON) | 全部数据导出成**已解密明文 JSON**，存到 `data/backup/export_时间戳.json`（⚠️ 别随便发人） |
| 备份数据（打包 zip） | 把整个 `data/` 打包成 `data/backup/backup_时间戳.zip` |
| 从备份恢复… | 选一个备份 zip，**覆盖**当前数据库与图片（二次确认） |
| 清空全部数据… | 清空数据库 + 原图 + 预处理图 + 缩略图（**两次确认**） |
| 使用说明（打开文档） | 打开项目 `docs/` 文件夹（本系列文档就在这里） |
| 关于 | 版本、运行模式、本地模型名、云端状态、题库数量、**加密自检结果**、数据目录 |

### 3.9 「设置」窗口
设置窗口是模态的（开着时不能操作主窗口），底部 `恢复默认` / `取消` / `保存`；
点保存后主窗口立刻用新配置重建识别与分析模块，**不用重启软件**。

**页签 1 运行模式**

| 选项 | 含义 |
| --- | --- |
| 纯本地（完全离线，隐私最强） | 不联网，全部在本机完成；速度取决于你的电脑 |
| 本地优先 + 云端兜底（推荐） | 本地识别不确定时自动用云端复核（需要 API Key） |
| 云端优先 | 直接交云端，最准但依赖网络，且会发送图片（可在隐私页关闭） |
| 置信度阈值 | 低于该值就转云端复核（0~1，越小越少用云端；默认 `0.70`） |
| 图片质量阈值 | 清晰度/亮度综合分低于该值直接转云端（默认 `0.35`） |
| 单图最多题目数 | 防止模型在一张图上啰嗦太多（默认 8） |
| 五个勾选框 | 导入后自动纠偏/提亮/锐化；识别出错题后自动生成分析报告；本地失败自动转云端；错题分析使用云端深度版；变式练习题由云端生成（最后一项是期望开关，当前变式题跟着深度分析一起由云端产出，单独取消它不会把变式题降回本地） |

**页签 2 本地模型**

| 选项 | 含义 |
| --- | --- |
| 服务类型 | `ollama`=本机 Ollama；`lmstudio`=LM Studio；`openai_compatible`=其它 OpenAI 兼容服务 |
| 服务地址 / 模型名称 | 例：`http://127.0.0.1:11434`、推荐 `qwen3-vl:4b`；旁边有 `刷新模型列表`、`测试连接` |
| `重新加载模型` | **识别突然变慢时点这个**（v1.0.1 起）。它把模型卸载后按当前空闲显存重新加载，并回报前后比例。原因见下方说明 |
| 识别超时(秒) | CPU 跑视觉模型可能很慢，默认 300 秒 |
| 送模型最长边 | 越小越快越省显存（默认 1600；显存紧张可调到 1100） |
| 压缩画质 | 送给模型前 JPEG 压缩质量（默认 88） |
| 服务程序路径 / 模型目录 / 数据目录 | Ollama 的 exe（留空自动探测，可 `浏览`）、模型存放目录（多盘部署如 `D:\ollama-models`）、`.ollama` 数据目录（受限环境时填） |
| 两个勾选框 | 启动软件时自动拉起本地模型服务（推荐）；关闭思考链（qwen3-vl 建议开启） |

> 💡 **为什么需要「重新加载模型」**：Ollama 只在**加载模型的那一刻**决定「多少层放显存、
> 多少层留给 CPU」，之后**不会**因为显存空出来而重新规划。所以如果模型是在显存紧张时
> （游戏、浏览器视频、LM Studio 等占着显存）被加载的，它会一直慢下去 ——
> 实测同一份代码、同一张图：**11% 上卡 = 6.6 tok/s（单图 78 秒）**，
> 点一次「重新加载模型」变成 **100% 上卡 = 74~80 tok/s（单图 6.7 秒）**。
> 三个地方会主动告诉你这件事：自检的「模型显存占用」项、识别时的运行日志
> （`识别偏慢（6.6 tok/s）：…`）、以及「刷新模型列表」后模型列表下面那行结论。

**页签 3 云端模型**

| 选项 | 含义 |

| ☑ 启用云端增强 | 总开关（等价于顶部 `☁` 按钮） |

**页签 4 隐私与存储**

## 4. 图片预处理怎么用
布局：左边一张大图（可拖拽框选），右边一列按钮和滑块，**每点一下左边立刻看到效果**，
右下角「已执行的处理」会一条条记下你做过什么。**照片有什么毛病，就用哪个功能：**

| 照片的问题 | 用什么 | 具体怎么点 |
| --- | --- | --- |
| 拍歪了（整页倾斜） | 自动纠偏 | 点 `🔍 自动检测倾斜并纠正`；提示"没有检测到明显倾斜（小于 0.3°）"就是真的不歪 |
| 歪得不多但看着别扭 | 微调角度 | `微调角度` 填 -15~15（步进 0.5），点 `应用` |
| 整张拍横了/拍倒了 | 旋转 90° | `↺ 左转 90°` 或 `↻ 右转 90°` |
| 太暗、发灰、像蒙了一层 | 一键优化 | 点 `✨ 自动纠偏 / 提亮 / 锐化`（纠偏 + 提亮 + 拉对比 + 轻度锐化 + 限尺寸） |
| 只是偏暗，不想一键处理 | 滑块 | 拖 `亮度`（-60~60）、`对比度`（0.6~1.8）、`伽马（提亮暗部）`（0.5~2.0）→ `应用明暗`；拖错了点 `重置明暗` |
| 有水印/印章压在字上 | 去水印 | 选 `🧽 去水印（框选要抹掉的区域）`，再在图上**框住水印** |
| 只想保留其中一道题 | 裁剪 | 选 `✂ 裁剪（框选要保留的区域）`，框住要留的部分，松手即裁 |
| 想整体回到原始照片 | 恢复原图 | 点 `↺ 恢复原图`（清空所有处理步骤） |
| 想确认这张图质量够不够 | 质量检测 | 看「综合 / 清晰度 / 亮度」，想重算点 `重新检测` |

**框选**：在图上按住左键拖出虚线框，松手立即生效；框太小（小于 6 像素）会被忽略。
裁剪是"**留下框里的**"，去水印是"**抹掉框里的**"，别搞反。三种去水印方式的区别（框选前先选好）：

| 方式 | 做法 | 适合 |
| --- | --- | --- |
| `inpaint`（默认） | 用区域四边的颜色做双向插值填充 | 印章、半透明水印压住了少量文字 |
| `median` | 只对这一小块做平滑 | 水印淡淡压字，抹白会留白斑 |
| `white` | 用周围纸张颜色直接盖住 | 水印在空白处（不压字） |

**处理完怎么生效**：点 `💾 保存处理结果（供识别/归档）`，图写到
`data/preprocessed/<原文件名>_<路径指纹>_edited.jpg`，并登记为这张图的"工作图"
（预览、归档目录里的 `_prep.jpg`、导出与打印都用它）。

保存之后这张图会被标记为**"手工处理过"**：下次点 `▶ 开始识别` / `重新识别本张` 时，
**识别直接使用你手工处理好的这张图**，不会再拿原图重跑一遍自动预处理
（运行日志里会出现「使用手工预处理后的图片进行识别」）。这是推荐的操作顺序：

```
载入编辑器 → 裁剪 / 纠偏 / 提亮 / 去水印 → 💾 保存处理结果 → ▶ 开始识别
```

> 💡 想回到"让程序自己自动预处理"的状态：点 `↺ 恢复原图` 后再点 `💾 保存处理结果`
> （等于用原图覆盖手工结果），或者干脆重新 `📁 导入图片` 一次。
> 整张图想重来就用 `云端重识别`，或先 `🗑 移除选中` 再重新导入。

**顺序建议**：① `✨ 一键优化` → ② 还歪就 `微调角度`/`自动检测倾斜` → ③ 去水印 →
④ 裁剪到只留需要的题 → ⑤ 看质量分（争取 0.6 以上）→ ⑥ `💾 保存处理结果` → ⑦ 回到
「识别与归档」点 `▶ 开始识别`（此时用的就是你刚保存的那张）。

## 5. 错题分析报告怎么读、怎么用
### 5.1 六段结构逐段解释
| 段落 | 里面是什么 | 你该怎么读 |
| --- | --- | --- |
| **一、错题还原** | 完整题干 + 你的答案 + 你的步骤 + 正确答案 | 先确认它还原得对不对。题干认错了就回「识别结果」改正 → `保存修改` → 重新生成 |
| **二、错误原因分析** | 带类型标签的原因清单，如 `[计算失误] 作答与正确答案非常接近（你写 1/2，正确是 1/3）` | 类型只有 8 种：审题失误、公式记错、知识点盲区、计算失误、思路偏差、粗心大意、书写不规范、时间不够。**看清类型再决定怎么补** |
| **三、对应知识点** | 知识点名（+ 课本出处）和一句重点说明 | 这是要回去翻课本的清单；别只看，抄一遍定义/公式 |
| **四、标准解题步骤** | 逐步可复现的解法，末尾给 `最终答案：…` | 盖住自己写的步骤重做一遍；卡在哪一步，问题就在那一步 |
| **五、避错技巧** | 针对本科目的可执行动作（如"算完回代检验"） | 挑 1~2 条抄到错题本封面，下次做题前看一眼 |
| **六、举一反三（变式练习）** | 1~2 道同类变式题，带答案和提示 | **这一段才真正提分**：当天做一遍，隔两三天再做一遍 |

报告末尾有一行来源标记：`（报告来源：本地模型生成｜引擎：local:qwen3-vl:4b）`。

### 5.2 数学公式是**教科书式排版**（重点）

报告里的数学不会显示成 `e^(2πik/6)`、`1/2` 这种纯文本，而是像课本一样排出来：

| 你看到的 | 写法 | 显示效果 |
| --- | --- | --- |
| 上下标 | `$x^2$`、`$x^{n-1}$`、`$a_{ij}$` | 真正的右上/右下小字（不是字面的 `^2`） |
| 分式 | `$\frac{-b\pm\sqrt{b^2-4ac}}{2a}$` | 上下两层 + 分数线 |
| **除法自动竖排** | 写成 `$k/n$`、`$v=s/t$`、`$e^{2\pi i k/n}$` 也行 | 会自动转成**上下分数**（`\frac{k}{n}`）—— 斜杠在角标里尤其难读，所以软件统一按课本的竖排来排 |
| 根号 | `$\sqrt{x+1}$`、`$\sqrt[3]{x}$` | 带罩住被开方数的横杠、可带次数 |
| 积分/求和/极限 | `$\int_0^1 x^2\,dx$`、`$\sum_{i=1}^{n} a_i$`、`$\lim_{x\to 0}$` | 上下限正确排在符号上下/右侧 |
| 矩阵行列式 | `$\begin{pmatrix} 1 & 2 \\ 3 & 4 \end{pmatrix}$`、`$\begin{vmatrix} … \end{vmatrix}$` | 圆括号矩阵 / 竖线行列式 |
| 希腊字母与符号 | `$\alpha$`、`$\pi$`、`$\le$`、`$\infty$` | α π ≤ ∞ |

- 这是**本地渲染**（纯 GDI，无需联网、无需 MathJax、无需装 LaTeX），所以离线也正常。
- **清晰度**：公式按 3 倍超采样渲染再缩回（每像素 9 个样本），小字号下也不发虚。
- **大小可调**：`设置 → 界面与公式 → 公式大小倍率`（默认 1.15 = 行高的 1.15 倍；
  嫌小就调到 1.3~1.5，嫌大调到 1.0）。同一页还能把「渲染精细度」调到 4 更清晰。
- 模型可能偶尔漏写 `$`（例如直接写 `x^2`），软件也能认出来并排版。
- **纯文本写法也认**：识别结果里常见的 `e^(2πik/6)`、`x^(n-1)+x^(n-2)+...+1` 会自动规范化成
  `e^{2πik/6}`、`x^{n-1}+x^{n-2}+...+1`（多余的外层括号会去掉，符合课本写法）。
- 已经是 Unicode 上标的写法（`S=πr²`）保持原样 —— 那种写法本身就能读，不折腾。
- 各处显示策略：**报告页**用图形排版；**题库/搜索列表**显示可读的纯文本写法（`x²`、`a/b`、`|1 2 3; …|`）；
  **TXT/Markdown 导出**同样是可读纯文本；**HTML 与 Word 导出**把公式作为图片内嵌，打印出来就是教科书样式；
  **PDF** 走浏览器打印时是图形排版，用内置渲染器时是可读纯文本。

### 5.3 三种报告的区别
| 版本 | 什么时候产生 | 特点 |
| --- | --- | --- |
| **本地规则版**（`rule`） | 本地模型没装好、或模型输出解析失败时的兜底 | 不调用任何模型，纯规则生成：还原题目、按简单规则猜原因、给通用避错技巧和"复习任务式"变式；**任何情况下都有一份可用报告** |
| **本地模型版**（`local`） | 正常点「生成/更新分析（本地模型）」 | 用本机模型写完整六段，离线可用；变式题有时偏空泛 |
| **云端深度版**（`cloud`） | 点「云端深度分析」，或按配置自动升级 | 归因更细、知识点更贴考纲、变式题是真正的同类题（换数值同考点）；若开了图片上传且模型支持视觉，还会看一眼原图，归因更准 |

云端分析成功时**以云端为主、本地补空**：云端没给全的字段（最终答案、避错技巧等）自动用本地版补上，
所以「云端深度版」不会比本地版更差。

### 5.4 建议的复习动线（三天一轮）
1. **当天**：识别 + 生成报告 → 看第二、四段 → 独立把标准解法重做一遍。
2. **当天稍后**：做第六段的变式题，做完对照答案。
3. **第 3 天**：左栏「题库」筛 `wrong` → 只看题干重做；做对了就在表单里把「状态」改成 `correct` → `保存修改`
   （统计看板的错题数会实时下降）。
4. **第 7 天**：搜这个知识点（第 6 节），把同类题集中做一遍；如果又错，回「错题分析」点 `🧠 生成/更新分析` 拿新变式题。
5. **考试前**：`⬇ 导出 ▾ → 导出知识点薄弱清单`，按"错题次数"从高到低刷。

## 6. 搜索与统计怎么帮我找薄弱点
### 6.1 搜索语法与范围
| 你输入 | 结果 |
| --- | --- |
| `导数` | 所有正文里含"导数"的题 |
| `导数 最值` | **空格 = AND**：同时含"导数"和"最值"的题（顺序无所谓） |
| 留空直接搜 | 按「全部」返回（上限 400 条） |
| 一个字的词（如 `熵`） | 也能搜，但会退化成全库比对，**稍慢**，属正常现象 |
| 英文大小写 | 不区分 |

**能搜到**：题干、选项、我的作答、我的解题步骤、参考答案、知识点、细分学科、题型、题号，
以及**错题分析报告的正文**（搜报告里写的"符号规则记反了"也能命中）。
**搜不到**：标签（标签只写进归档文字稿和导出文档，不参与搜索过滤）、图片里的字。

### 6.2 用统计看板找薄弱点
打开「统计看板」，按这个顺序看：
1. **薄弱知识点（红色柱状图）**：排第一的就是最该补的。记住关键词 → 去「全局搜索」搜它 → 同类题集中重做。
2. **错误原因分布**：若"计算失误/粗心大意"占大头，说明不是不会，是练得太快，该慢下来 + 回代检验；
   若"知识点盲区"占大头，回去看课本和例题。
3. **学科占比饼图**：某科占比极低但考试占比高？那就是你的"回避科目"。
4. **题型分布**：解答题错多说明步骤书写有漏洞；选择题错多说明审题有漏洞。

**闭环动线**：看板发现薄弱点 → 搜索同类题 → 生成/更新报告 → 做变式题 → 状态改为 `correct`
→ 导出薄弱清单打印 → 一周后再回看板对比。

### 6.3 知识点薄弱清单
`⬇ 导出 ▾ → 导出知识点薄弱清单…` 生成一份按错题次数排序的表，并给建议：
**≥3 次 = 优先复习**、**2 次 = 需要巩固**、**1 次 = 保持关注**。
表格后面还有「错题明细」，每个知识点下列出对应错题的题号和题干前 70 字，直接照着刷。

## 7. 导出与打印
### 7.1 五种格式怎么选
| 格式 | 内容 | 优点 | 缺点 / 注意 |
| --- | --- | --- | --- |
| **Markdown (`.md`)** | 全部文字（题干、作答、答案、报告六段），**不含图** | 体积小、方便再加工 | 需要支持 md 的阅读器 |
| **纯文本 (`.txt`)** | 同上去掉 Markdown 记号 | 万能、任何设备能开 | 排版最简单，**不含图** |
| **网页 (`.html`)** | 文字 + **图片以 base64 内嵌** | **单个文件**，发到手机上直接看，排版好看 | 图多时文件变大 |
| **Word (`.docx`)** | 文字 + 内嵌图片（宽限 520 像素内） | **能直接编辑**、加批注、改完再打印；用内置生成器，不需要装 Office | 改之前建议另存一份 |
| **PDF (`.pdf`)** | 文字 + 图片 | 打印最稳，发别人不会乱版 | 见 7.3 的两种引擎说明 |

### 7.2 三种预置文档
| 菜单项 | 内容 |
| --- | --- |
| 导出全部错题（个人错题本）… | 全部 `wrong` 的题 + **完整错题分析报告** + 题目图，直接打印装订就是错题本 |
| 导出知识点薄弱清单… | 薄弱知识点表（含建议）+ 每个知识点下的错题清单 |
| 导出错题汇总… | 总览统计 + 学科分布 + 错误原因分布 + 错题明细（题干、我的答案、正确答案），**不含完整分析**，适合快速浏览 |

另外两个菜单项：`导出选中题目…`（要先在左栏「题库」里选中）、`导出全部题目…`（所有状态都导）。
各入口支持的格式略有差别：**选中题目 / 个人错题本 / 全部题目** 支持 Word、PDF、Markdown、纯文本、网页；
**知识点薄弱清单 / 错题汇总** 支持 Markdown、纯文本、网页、Word（**这两个没有 PDF**，想打印先存 Word 再打印）。
单题导出还有两个入口：「识别结果」区的 `📄 导出本题`、「错题分析」页的 `📄 导出本报告`（Markdown/纯文本/网页）。

### 7.3 PDF 的两种生成方式（很重要）
导出 PDF 时软件按顺序尝试：
1. **优先用系统里的 Edge / Chrome 无头打印**：生成的是**正常 PDF，文字可选中、可复制、可搜索**，体积小、排版最好。
2. **找不到浏览器时用内置渲染器**：把每页文字用系统字体渲染成图片再塞进 PDF（中文绝不会变方块或乱码，
   完全离线可用）。代价是**文字不可选中**、体积略大，并且内置版会把每道题的**原图整页放在前面**、
   文字页跟在后面。

`环境自检` 里的「PDF 导出（浏览器打印）」一项会告诉你走的是哪条路；想要可选文字的 PDF，装个 Edge/Chrome 即可。

### 7.4 打印建议
- **错题本**：导出 `.docx` → 在 Word 里加页眉页脚/两栏排版 → 打印。
- **只想打印某些题**：在「题库」里按住 Ctrl 多选 → `导出选中题目…`。
- **手机上翻**：导出 `.html`，用微信发给自己，点开就能看，图片都在文件里。
- **给老师看一道题的讲解**：`📋 复制报告` 直接粘进聊天窗口，比发文件快。

## 8. 归档目录结构说明
归档是"成果落地"部分：**不打开软件，用资源管理器也能翻，能按学科打印，能拷给同学。**
数据库只是索引，归档目录才是看得见摸得着的错题本。

### 8.1 两个模板
**目录模板**（设置 → 归档 → 目录模板，默认 `{subject}/{grade}/{qtype}/{status}`）：

| 变量 | 会变成 |
| --- | --- |
| `{subject}` / `{subject_detail}` | 学科，如 `数学` / 细分学科，如 `高等数学` |
| `{grade}` / `{qtype}` | 学段 `高中` / 题型 `选择题` |
| `{status}` | 状态中文：`错题` / `正确题` / `未做题` / `未判定` |
| `{year}` / `{month}` | 入库年份 / 月份，如 `2026` / `09` |
| `{source}` | 来源标注（界面暂未提供填写入口，默认 `未标来源`） |

例：把模板改成 `{subject}/{year}-{month}/{status}`，归档就按"学科/年月/状态"分层。
**文件名模板**（默认 `{uid}_{status}`）可用 `{uid} {status} {subject} {qtype}`；
非法字符（`\ / : * ? " < > |`）会自动替换成 `_`，不用担心学科名里有奇怪符号。

### 8.2 真实目录树示例
本机跑过一遍示例题之后，`data/归档/` 的真实样子：
```
data/归档/
├── 数学/
│   ├── 高中/
│   │   └── 选择题/
│   │       ├── 错题/    Q20260917-0002_错题.jpg / .md / _prep.jpg
│   │       ├── 正确题/  Q20260917-0001_正确题.jpg / .md / _prep.jpg
│   │       └── 未做题/  Q20260917-0003_未做题.jpg / .md / _prep.jpg
│   └── 大学/
│       └── 填空题/
│           ├── 正确题/  Q…-0004、Q…-0005 各三个文件
│           └── 未做题/  Q…-0006 三个文件
└── 归档索引.md        ← 点「更多 → 重建归档索引」生成：统计 + 各学科题量 + 薄弱知识点
```

### 8.3 每个题目目录里的 4 类文件
| 文件 | 内容 | 什么时候有 |
| --- | --- | --- |
| `<文件名>.jpg`（或原扩展名） | 原图副本 | 勾了「归档时保留原图」时 |
| `<文件名>_prep.jpg` | 预处理图（纠偏/提亮后的工作图） | 有工作图时 |
| `<文件名>.md` | **文字稿**：学科/学段/题型/难度/知识点/识别引擎与置信度/来源图片/标签 + 题干 + 选项 + 我的作答 + 参考答案（有报告时还附报告全文） | 勾了「归档时写 Markdown 文字稿」时 |
| `<文件名>_错题分析.md` | 单独的错题分析报告，**方便直接打印某道题的讲解** | 有报告且勾了「归档时写错题分析报告」时 |

> 归类逻辑：一图多题时每道题单独一个目录；识别时无法判定对错状态的题会被**保守地按「未做题」**
> 归档（避免被误当成错题要求写分析），你确认后把状态改成 `wrong` 再保存即可。

## 9. 数据安全与备份
### 9.1 数据都在哪
- `data/archive.db` —— SQLite 数据库（题库、报告、标签、检索索引）
- `data/master.key` —— **本机加密主密钥**（32 字节随机数，首次运行生成，权限尽量收紧）
- `data/config.json` —— 配置（模式、模型、隐私、归档模板…）
- `data/images/导入_年月日_时分秒/` —— 导入时复制的原图副本（按批次分文件夹）
- `data/preprocessed/` —— 流水线预处理图 `<原名>_prep.jpg` 与手工处理图 `<原名>_<指纹>_edited.jpg`
- `data/归档/` —— 归档成果（第 8 节）；`data/backup/` —— 备份 zip 与导出的 JSON
- `data/logs/app.log` —— 运行日志；`data/thumbs/` —— 缩略图缓存（可随时删）

整个软件是**绿色便携**的：拷贝 `data/` 就能迁移到另一台电脑；也可以用环境变量 `EXER_HOME`
把根目录指到 D 盘或 U 盘。

### 9.2 加密怎么做的（够用就好）
- 算法：ChaCha20 流加密 + HMAC-SHA256 认证（Encrypt-then-MAC），密钥由「`master.key` + 可选口令」
  经 PBKDF2-HMAC-SHA256（20 万轮）派生，每个值都有独立随机 salt/nonce。
- **加密的字段**：题干、选项、我的作答、我的步骤、参考答案、错题报告正文、图片备注。
- **保持明文的字段**（本身不含隐私，且建目录/统计要用）：学科、细分学科、学段、题型、状态、难度、
  知识点名称、置信度、引擎、文件路径、来源、批次、时间；报告表里另存了明文的"错误原因类型 + 知识点名称"两份小列表用于统计。
- **加密了还能搜索**：正文不存明文，但把文本切成 2-gram/3-gram 的 **HMAC 指纹**写进索引表，
  查询时把关键词算成同样的指纹去匹配，命中后再解密逐条校验——"库里没有明文，也能搜到关键词"。
- 界面「关于」里的**加密自检**用 RFC 8439 官方测试向量验一遍实现，正常显示"通过"。

⚠️ 两点提醒：① 加密目标是"本地文件不裸奔"（别人拷走 `archive.db` 读不出题干与报告），
不是抵抗专业攻击者；② `master.key` 与数据库是一对，**备份 zip 里包含 `master.key`**，
所以从备份恢复后能正常读；但如果你单独把 `master.key` 删了，加密正文就再也解不开了。

### 9.3 备份 / 恢复 / 清空
| 做法 | 入口 | 结果 |
| --- | --- | --- |
| 整包备份（推荐） | `更多 ▾ → 备份数据（打包 zip）` | `data/backup/backup_时间戳.zip`，含数据库、配置、密钥、原图、归档、日志（不含 `backup/` 自身） |
| 明文数据导出 | `更多 ▾ → 导出全部数据 (JSON)` | `data/backup/export_时间戳.json`，已解密，便于迁移与二次加工（⚠️ 明文） |
| 手动 | 直接复制整个 `data/` 文件夹 | 最土但最可靠 |

建议节奏：**每周一次 zip 备份**并放到另一个盘或网盘；整理完一学期的错题后做一次整目录复制。

**从备份恢复**：`更多 ▾ → 从备份恢复…` → 选 zip → 确认（提示"恢复会用备份包覆盖当前数据库与图片"）。
过程是：关闭数据库连接 → 把 zip 解压**覆盖**到 `data/` → 重新打开数据库 → 刷新界面。
⚠️ 恢复是**覆盖**不是合并，想保留当前数据就先备份一次当前状态。

**清空全部数据**：`更多 ▾ → 清空全部数据…`，会连问两次（第一次就提示"建议先点备份数据"）。
清空范围 = 数据库全部表（题目、报告、标签、检索索引、图片记录）+ `data/images/`、`data/preprocessed/`、
`data/thumbs/` 里的文件。**注意**：`data/归档/` 里的文件**不会**被自动删除（那是你的成果文件），
要自己在资源管理器里清理；`data/backup/` 里的备份也不受影响。

## 10. 效率技巧
1. **整本练习册一次性倒入。** 所有照片塞进一个文件夹（可以有子文件夹）→ `📂 导入文件夹` →
   点一次 `▶ 开始识别` 去喝水。想更省事或不想开界面时，用命令行跑：
   `python tools/import_cli.py 照片目录 --json 报告.json`（流程与界面完全一致：导入 → 预处理 → 识别 →
   入库 → 归档 → 错题分析；可加 `--force local` 强制本地、`--no-analyze` 不写分析、`--no-archive` 不归档）。
2. **先预处理再识别，省很多人工核对。** 歪的、暗的、有水印的先走一遍「图片预处理」
   （`✨ 一键优化` + 去水印），**点 `💾 保存处理结果`**，再回「识别与归档」点 `▶ 开始识别`——
   识别会直接用你手工处理好的那张图（不再自动预处理），质量分上去后识别更准，云端兜底也更少被触发（省钱省时间）。
3. **一图多题先裁开。** 一张照片 5 道题只想留第 3 题？预处理里裁到只剩它，保存后再识别，
   识别结果里就只会有这一道题。
   顺便说：单图最多题目数默认 8（设置 → 运行模式），超出的部分不会被识别。
4. **用标签替代"来源标注"。** 界面没有单独的"来源"输入框，最实用的做法是在「识别结果」的**标签**里写清楚，
   如 `2025春季练习册P32`、`期末模拟卷A`；标签会写进归档文字稿和导出文档。
   （归档目录模板里的 `{source}` 变量目前没有界面入口，默认"未标来源"。）
5. **云端只用来做深度分析，最省钱。** 设置 → 运行模式：模式选「纯本地（完全离线）」，
   同时把「置信度阈值」从 0.70 降到 0.5、「图片质量阈值」从 0.35 降到 0.2（阈值越低兜底越少触发）；
   云端模型页填好 Key，并保持「错题分析使用云端深度版」勾选。
   这样**识别阶段完全不出网**（纯本地模式是硬保证），只有错题报告调用云端——识别是"每张图都要发"的大头，
   分析是"每道错题发一次"的小头。（注意：模型要联网下载一次；下载完之后识别全程离线。）
6. **想 100% 不出网，两步都做更放心。** ①运行模式选「纯本地（完全离线）」——识别阶段**绝对不会**调用云端，
   与「云端增强」开关、有没有 Key 都无关；②再把顶部 `☁ 云端增强` 关掉——连错题分析的云端深度版也不走。
   要更彻底还可以在隐私页取消「允许把图片传给云端模型」、清空 API Key。
   （想验证的话：选纯本地跑一张图，`data/logs/app.log` 里不会出现任何「云端识别」「触发云端兜底」字样。）
7. **一张图识别错了，别急着整批重来。** 在左栏点中那张图 → `本地重识别` / `云端重识别`，
   或双击列表行只识别这一张；整批重跑会产生重复题号，重跑前先用 `🗑 移除选中` 清掉已识别的。
8. **手动修正才是精度的最后一道闸门。** 看「置信度」列，低于 0.70 的一律人工过一眼；
   改完**一定要点 `💾 保存修改`**，「状态」字段尤其重要——它决定这道题是否写报告、归到"错题"还是"正确题"目录。
9. **每题都填「我的步骤」。** 报告对"错在哪一步"的判断极度依赖它，哪怕只写两行，报告质量也明显不同。
10. **每整理完一章，导出一次薄弱清单。** 打印出来贴在书桌上，一周后回「统计看板」看
    "薄弱知识点"柱状图有没有变矮，比刷题量更有成就感。

## 11. 常见疑问速查表
完整排查步骤、日志关键字与解决办法都在 [`03-常见问题排查.md`](03-常见问题排查.md)。

| # | 问题 | 快速答案 |
| --- | --- | --- |
| 1 | 双击 `启动.bat` 没反应 | 改用 `启动-控制台.bat` 看报错；常见原因是没装 Python 或没勾 tcl/tk |
| 2 | 识别一直卡住或特别慢 | CPU 跑视觉模型本来就慢；把「送模型最长边」调到 1100、「单图最多题目数」调小，或在设置里 `测试连接` 确认模型在跑 |
| 3 | 提示"本地模型服务未就绪" | 点 `环境自检` 看"本地模型服务"那一行；必要时手动 `ollama serve`、`ollama pull qwen3-vl:4b` |
| 4 | 一张图识别出 0 道题 | 先 `载入编辑器` 提亮/纠偏再重识别，或 `云端重识别`；仍不行就在「识别结果」里手动录入 |
| 5 | 一图多题只认出一部分 / 认多了 | 单图最多题目数默认 8；多余的题到「题库」里 `删除选中题`，漏掉的题手动补录 |
| 6 | 状态判错了（错题被记成未做题） | 在「识别结果」把「状态」改成 `wrong` → `保存修改` → 再点 `🧠 生成错题分析` |
| 7 | 题库里出现重复题目 | 多半是同一张图重复识别了；识别前先 `🗑 移除选中`，再删掉重复题 |
| 8 | 导出的 PDF 文字复制不了 | 你走的是内置渲染器（没找到 Edge/Chrome）；装 Edge 或 Chrome 后重导即可 |
| 9 | 导出的 Word 打不开 / 乱码 | 确认扩展名是 `.docx`（不是 `.doc`）；确实异常就把文件与「运行日志」页内容一起发出来 |
| 10 | 归档目录是空的 | 检查设置 → 归档里「归档时写 Markdown 文字稿」是否被关掉；或用 `🗂 归档选中` 手动补一次 |
| 11 | 搜索搜不到明明存在的题 | 换更长的关键词（单字查询会走全库比对，较慢）；确认搜的是正文而不是标签 |
| 12 | 怕数据丢 | 数据都在 `data/`；「清空全部数据」只删数据库与图片，归档目录要手动清；`master.key` 千万别单独删 |

## 附录：运行模式、云端兜底与进阶配置
| 模式 | 识别流程 | 联网情况 |
| --- | --- | --- |
| `local_only` 纯本地（离线） | 本地模型识别为主 | **识别阶段绝不调用云端**（硬保证，与云端增强开关、Key 都无关）；想让错题分析也不联网，再关掉顶部 `☁ 云端增强`（见第 10 节第 5、6 条） |
| `hybrid` 本地优先 + 云端兜底（默认） | 本地识别 → 不确定就云端复核 → 结果合并 | 只有兜底时才联网 |
| `cloud_first` 云端优先 | 直接云端识别；云端失败自动退回本地 | 每次都联网（是否发图取决于隐私开关） |

**触发云端兜底的条件**（前提："云端可用"= 云端增强已开且当前档案填了 API Key，且模式不是「云端优先」）：

| 顺序 | 触发条件 | 对应设置 |
| --- | --- | --- |
| 1 | 本地识别失败 / 没执行 | 运行模式页「本地失败自动转云端」（默认开） |
| 2 | 本地一道题都没识别出来 | 无单独开关 |
| 3 | 有题目置信度低于阈值（默认 0.70） | 「置信度阈值」 |
| 4 | 有题目无法判定对错状态（unknown） | 无单独开关 |
| 5 | 图片质量分低于阈值（默认 0.35） | 「图片质量阈值」 |
| 6 | 图片清晰度低于 40（明显偏模糊） | 与第 5 条同一个开关 |

合并规则：本地与云端都有结果时**以云端为主**，本地补上云端缺的细节（学科/学段、更完整的题干、知识点、
以及云端判成 unknown 的状态）；状态仍是 unknown 的题入库时按「未做题」保存。

**配置文件里的进阶项**（`data/config.json` 里有、设置窗口没画出来，一般不用动）：
`run.auto_skew` / `run.auto_brighten` / `run.auto_sharpen`（自动预处理时是否分别纠偏/提亮/锐化，默认都开）、
`run.fallback_on_low_confidence` / `run.fallback_on_blur`（置信度低 / 模糊时是否允许转云端，默认都开）、
`run.max_concurrency`（预留项，当前版本识别是**串行**的）、
`local.num_ctx` / `local.temperature` / `local.keep_alive`（默认 `8192` / `0.1` / `10m`）、
`ui.font_family` / `ui.font_size` / `ui.image_display_max`（默认 `微软雅黑` / `10` / `1200`）、
`ui.window`（自动记住窗口位置与大小）、
`cloud.profiles[].timeout` / `max_tokens` / `temperature`（默认 `180` / `4096` / `0.3`）。
