# 03 · 常见问题排查（FAQ）

> 适用版本 **v1.0.0**（Python 3.8+ / tkinter / 零第三方依赖；本地 Ollama 或 LM Studio 视觉模型 + 云端 OpenAI 兼容接口兜底）。文中每条「解决办法」都与代码一致，涉及的设置项都能在界面上或 `data/config.json` 里找到，命令可直接复制到 Windows 的 `cmd` / PowerShell。
> 排查顺序：进程起不来（一）→ 模型不通（二）→ 识别不对（三）→ 云端报错（四）→ 导出不对（五）→ 数据找不到（六）。

---

## 0. 出问题先做这三件事（30 秒定位 90% 的问题）

| 步骤 | 操作 | 能看到什么 |
| --- | --- | --- |
| 1 | 双击 **`环境自检.bat`**（= `python tools\selfcheck.py`） | 各项 ✅/⚠️/❌ 与「↳ 建议」，结尾给出「失败 N 项，警告 N 项」 |
| 2 | 双击 **`启动-控制台.bat`**（= `python -m exerarchive`） | 真正的 Python 报错堆栈；启动失败会弹「启动失败」对话框 |
| 3 | 打开 **`data\logs\app.log`**（界面：更多 ▾ → 查看运行日志文件，或「运行日志」页签） | 每张图的引擎、路由、质量分、云端兜底原因、失败原因 |

```bat
cd /d C:\deepseek\exercise-archive
python tools\selfcheck.py              :: 人类可读报告
python tools\selfcheck.py --no-model   :: 跳过模型实测，更快
python tools\selfcheck.py --json       :: 机器可读（见第七章）
python -m exerarchive --selfcheck      :: 等价写法（走程序入口）
python -m exerarchive --version        :: 版本号
```

> 💡 自检共 **18 个检查项 / 7 组**（见 `tools/selfcheck.py`）：①环境（Python、tkinter、磁盘）②存储（数据目录可写、加密自检、数据库）③图像（解码后端、GDI+、中文字体渲染、公式排版）④**显卡占用**（nvidia-smi 的利用率与空闲显存，被游戏/渲染占满时识别会变慢甚至超时，见附录二）⑤本地模型（服务是否在跑、已装模型、**模型显存占用**、视觉实测）⑥云端配置 ⑦导出能力（PDF 浏览器、Word 内置生成器、归档目录）。其中「模型显存占用」只在模型**当前驻留**时才出现；启用云端增强、跑模型视觉实测时还会各多一项，所以实际是 **17~20 项**。加 `--json` / `--out 文件` 可拿到机器可读结果（见第七章）。

## 一、启动类问题（8 条）

### 1.1 双击「启动.bat」完全没反应，任务管理器里也看不到进程

- **现象**：双击后既没有窗口，也没有黑窗口一闪。
- **原因**：`启动.bat` 依次找 `py` → `pythonw` → `python`，找到前两个时用 `start "" pyw/pythonw -m exerarchive` 启动，**它们都没有控制台**：解释器不对或程序导入阶段就退出时，你什么都看不到。另外从压缩包/网盘来的 `.bat` 可能被标记为「来自 Internet」。
- **解决办法**：
  1. 先用带控制台的入口，一定能看到原因：`启动-控制台.bat`；
  2. 看解释器在哪：`where py` / `where python` / `where pythonw`；
  3. 解锁被阻止的文件：右键 `启动.bat` → 属性 → 勾「解除锁定」→ 确定；或整目录 `Get-ChildItem C:\deepseek\exercise-archive -Recurse | Unblock-File`（PowerShell）；
  4. 绕开 bat 直接启动：`py -3 -m exerarchive`。
- **还是不行怎么办**：确认目录里真的有 `exerarchive\__main__.py`；若 `py -3 -m exerarchive` 报 `No module named exerarchive`，说明你不在程序目录（bat 里有 `cd /d "%~dp0"`，手工敲命令要自己先 `cd`）。

### 1.2 黑窗口一闪而过（启动后立刻闪退）

- **现象**：黑窗口出现又消失，软件没打开。
- **原因**：启动阶段抛异常。`exerarchive\ui\app.py` 的入口会打印堆栈并尝试弹「启动失败」对话框（提示「请运行『环境自检.bat』查看详细原因」），但**连 tkinter 都不可用时这个兜底弹窗也弹不出来**，于是表现为静默闪退。
- **解决办法**：
  1. 带控制台跑：`启动-控制台.bat`；
  2. 看日志尾部：`Get-Content C:\deepseek\exercise-archive\data\logs\app.log -Tail 50`；
  3. 跑自检定位最常见的两类失败（tkinter 不可用、数据目录不可写）：`python tools\selfcheck.py`。
- **还是不行怎么办**：保留控制台输出的最后 15 行 + 日志尾部（收集方式见第七章）。若含 `TclError`、`Can't find a usable init.tcl`，按 1.4 处理。

### 1.3 提示「'python' 不是内部或外部命令，也不是可运行的程序」

- **现象**：`启动-控制台.bat` 报这一句，或 `where py` 没有任何输出。
- **原因**：安装 Python 时没勾「Add python.exe to PATH」；或 Microsoft Store 的「应用执行别名」假 `python.exe` 抢先（敲 `python` 会弹应用商店）。
- **解决办法**：
  1. 重装 Python（3.8+，推荐 3.12），安装第一屏勾 **Add python.exe to PATH**；
  2. 临时救急（只对当前窗口有效）：`set PATH=%PATH%;%LOCALAPPDATA%\Programs\Python\Python312` 然后 `python -V`；
  3. 永久生效（**改完要重开命令行**）：PowerShell 里 `setx PATH "$env:PATH;$env:LOCALAPPDATA\Programs\Python\Python312"`；
  4. 关掉商店别名：设置 → 应用 → 高级应用设置 → 应用执行别名 → 关闭 `python.exe`、`python3.exe`；
  5. 不想改 PATH 就用绝对路径：`"%LOCALAPPDATA%\Programs\Python\Python312\python.exe" -m exerarchive`。
- **还是不行怎么办**：确认装的是 Windows 安装版而非嵌入式 zip 版（嵌入式版既没有 tkinter 也没有 py 启动器）；用 `python -c "import sys;print(sys.executable)"` 看它指向哪个 exe，指向 `WindowsApps` 就是商店别名，按第 4 步关掉。

### 1.4 `ImportError: No module named tkinter` / `ModuleNotFoundError: No module named 'tkinter'`

- **现象**：控制台报 tkinter 错误；自检「图形界面库 tkinter」为 ❌「不可用：…」。
- **原因**：界面完全基于标准库 tkinter/ttk，**不装第三方包也要有 tcl/tk 运行时**。Windows 重装 Python 时没勾「tcl/tk and IDLE」，或用嵌入式版、精简系统、某些 WSL/conda 环境就会缺。
- **解决办法**：
  1. 先确认：`python -c "import tkinter; print(tkinter.TkVersion)"`；
  2. Windows：重跑安装包 → Modify → 勾 **tcl/tk and IDLE**（自检给的原文建议就是「Windows 下重装 Python 时勾选 tcl/tk；Linux 需装 python3-tk」）；
  3. Linux：`sudo apt install python3-tk`（Fedora 用 `sudo dnf install python3-tkinter`）；
  4. macOS：用 python.org 官方包，或 `brew install python-tk`。
- **还是不行怎么办**：系统里常同时有多个 Python（商店版/Anaconda/官方版），确认 `python -c "import tkinter"` 用的那个与启动软件用的是同一个。自检本身不需要界面，可先把「Python 版本 / 数据目录 / 加密 / 数据库」验完。

### 1.5 界面或控制台中文变成方块、问号、`锟斤拷`

- **现象**：控制台中文乱码；或界面按钮文字全是方块。
- **原因**：控制台乱码多因代码页/字体（两个 bat 里已写 `chcp 65001`，但若用 ANSI 重新保存过就失效，或 conhost 字体不含中文）；界面方块则是系统里一个中文字体都没有——界面字体由 `pick_font_family()` 按「微软雅黑 → Microsoft YaHei UI → Microsoft YaHei → PingFang SC → Noto Sans CJK SC → SimHei → DengXian → SimSun」挑选，都没有时退回 `TkDefaultFont`。
- **解决办法**：
  1. 控制台手动切代码页并把字体改成「新宋体」或「MS Gothic」：`chcp 65001`；
  2. 让 Python 强制 UTF-8：`set PYTHONUTF8=1` 与 `set PYTHONIOENCODING=utf-8`；
  3. 界面字体（**界面上没有入口**，改配置后重启）：`data/config.json` → `"ui": { "font_family": "微软雅黑", "font_size": 10 }`；
  4. 安装中文字体：设置 → 时间和语言 → 语言 → 中文(简体) → 语言选项 → 可选字体功能。
- **还是不行怎么办**：归档 `.md` 与导出的 HTML/Word 都是 UTF-8，**别用 GBK 老编辑器（含旧版 Excel）打开 `.md`**，用记事本/VS Code 就正常。PDF 里中文是方块属于导出字体问题，见 5.4。

### 1.6 程序放在中文目录、带空格目录或 OneDrive 同步盘里

- **现象**：偶发 `database is locked`、写入失败、出现 `archive (1).db` 之类的同步冲突副本；深层归档路径写不进去。
- **原因**：代码用 `pathlib` + UTF-8 处理路径，**中文路径本身没问题**；真正的坑有三个——① 数据库是 **WAL 模式**（旁边有 `archive.db-wal`、`archive.db-shm`），同步盘实时抓这些文件会导致锁库与冲突副本；② 放在 `C:\Program Files` 等无写权限位置（见 1.8）；③ 归档是「学科/学段/题型/状态/文件名」多层路径，叠加深目录会超 260 字符限制。
- **解决办法**：
  1. 移到纯英文短路径：`robocopy "C:\Users\你\OneDrive\桌面\exercise-archive" "D:\exerarchive" /E /COPY:DAT`；
  2. 右键 OneDrive 图标 → 设置 → 同步并备份 → 管理备份 → **停止同步这个文件夹**；
  3. 只把数据放别处（代码原地不动）：`setx EXER_HOME "D:\exerarchive-data"`，**重启软件**；
  4. 开启长路径（管理员）：`New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name LongPathsEnabled -Value 1 -PropertyType DWord -Force`。
- **还是不行怎么办**：关掉软件后删除 `archive.db-wal` / `archive.db-shm`（**只能软件退出后删**）再启动；同步盘的冲突副本不要拿来覆盖 `archive.db`，先按 6.3 从备份恢复。

> ⚠️ `EXER_HOME` 会把 `data\` 指到新位置，程序还会在它下面找 `samples\`（示例图），所以请把它当成「程序根目录」而不是「仅数据库目录」。

### 1.7 杀毒软件报毒 / `启动.bat` 或 `ollama.exe` 被隔离

- **现象**：杀软弹窗拦截、文件被删或隔离、双击 bat 提示「操作已被系统管理员阻止」。
- **原因**：误报来自三类行为——bat 调起无窗口进程（`pythonw`/DETACHED_PROCESS）、程序读写 `data\*.db` 与 `data\master.key`、Ollama 监听本地端口。属启发式误报，不是病毒行为。
- **解决办法**：
  1. Windows Defender（管理员 PowerShell）：`Add-MpPreference -ExclusionPath "D:\exerarchive"`（模型目录也加一条）；
  2. 图形界面：Windows 安全中心 → 病毒和威胁防护 → 管理设置 → 排除项 → 添加文件夹；
  3. 360/火绒/管家：把程序目录加进信任区，并把 `python.exe`、`pythonw.exe`、`ollama.exe` 加入信任进程；
  4. 若 `data\master.key` 被「隐私保险箱」类软件加密，题干会显示空白，见 6.5。
- **还是不行怎么办**：从隔离区恢复被删文件，确认 `启动.bat`、`启动-控制台.bat`、`环境自检.bat`、`exerarchive\` 都在；缺 `data\master.key` 时**先别启动软件**（会生成新密钥），先从备份恢复（6.3）。

> ⚠️ 只做「目录排除」，不要为了装这个软件而整体关闭杀毒或防火墙。

### 1.8 `sqlite3.OperationalError: unable to open database file`（data 目录没有写权限）

- **现象**：启动或自检时报打不开数据库；自检「数据目录可写」「数据库」都是 ❌。
- **原因**：`Store` 打开 `data\archive.db`，必须能在 `data\` 里创建/写入文件与 WAL 文件。放在 `C:\Program Files`、只读 U 盘、被策略限制的用户目录或磁盘写满都会报这一句；自检给的处置建议就是「把软件放到有写权限的目录（不要放 C:\Program Files）」。
- **解决办法**：
  1. 先跑自检（该项就是往 `data\.write-test` 写一个 `ok` 再删）：`python tools\selfcheck.py --no-model`；
  2. 换目录：`robocopy "C:\deepseek\exercise-archive" "D:\exerarchive" /E /COPY:DAT`；
  3. 原地授权（管理员命令行）：`icacls "D:\exerarchive" /grant "%USERNAME%":(OI)(CI)F /T`；
  4. 查磁盘与占用：`Get-PSDrive D`、`Get-Process | Where-Object { $_.ProcessName -match 'ollama|python' }`。
- **还是不行怎么办**：自检建议「检查 data 目录权限，或删除 data/archive.db 重建」——**重建会丢题目**，所以顺序必须是：整目录备份 `data\` → 把 `archive.db` 改名为 `.bak` → 重启生成新库 → 确认能起来后再按 6.3 恢复。`data\test_store.db`、`test_store_plain.db` 是测试残留，删掉不影响使用。

## 二、模型类问题（8 条）

### 2.1 本地模型服务没起来（端口 11434 / 1234 连不上）

- **现象**：自检「本地模型服务 未运行（ollama @ http://127.0.0.1:11434）」为 ❌；设置里「测试连接」提示「连接失败 ❌：本地模型服务不可用」；状态栏出现「本地模型服务未就绪（可在设置里检查）」。
- **原因**：程序按 `local.base_url` 拆出主机与端口，先做 TCP 连接测试，再请求 `/api/version`（Ollama）或 `/v1/models`（LM Studio / 其它 OpenAI 兼容服务）确认是「真服务」而不是别的程序占了端口。Ollama 默认 11434，LM Studio 默认 1234。
- **解决办法**：
  1. 手工验证：`Test-NetConnection 127.0.0.1 -Port 11434`、`curl.exe http://127.0.0.1:11434/api/version`；LM Studio 用 `curl.exe http://127.0.0.1:1234/v1/models`；
  2. 让程序自动拉起：设置 → 本地模型 → 勾 **启动软件时自动拉起本地模型服务（推荐）**（`local.auto_start`，默认已开），并确认 **服务程序路径**（`local.server_exe`）指向 `ollama.exe`；程序执行的是 `ollama serve`，LM Studio 执行 `lms server start`；
  3. 手工启动看报错（前台跑）：`"C:\deepseek\ollama\ollama.exe" serve` 或 `lms server start`；LM Studio 图形界面做法是打开它 → Developer（本地服务）→ Start Server；
  4. 查端口占用：`netstat -ano | findstr :11434` 再 `tasklist | findstr <PID>`。
- **还是不行怎么办**：让设置里三项互相对齐——**服务类型 / 服务地址 / 服务程序路径**（Ollama→`ollama`+11434；LM Studio→`lmstudio`+1234；其它本地服务选 `openai_compatible` 并填它自己的地址）。换过端口时三处都要改。

### 2.2 `ollama pull` 失败或特别慢（国内网络）

- **现象**：`ollama pull qwen3-vl:4b` 速度极低、`i/o timeout`、`unexpected EOF`；识别一直等模型。
- **原因**：视觉模型体积大（GB 级），下载走境外源；同时自检「磁盘剩余空间」低于 2GB 会给 ⚠️「建议清理磁盘，模型与图片都比较占空间」。
- **解决办法**：
  1. 看现状：`ollama list`、`python tools\selfcheck.py --no-model`；
  2. 设代理后重试（改完**重启 Ollama**）：`set HTTPS_PROXY=http://127.0.0.1:7890`、`set HTTP_PROXY=http://127.0.0.1:7890`，再 `ollama pull qwen3-vl:4b`；永久生效用 `setx HTTPS_PROXY "http://127.0.0.1:7890"`；
  3. 断点续传：直接重复执行同一条 `ollama pull`，不必删已下载的分片；
  4. 空间紧张时先把模型目录指到大盘（见 2.7）。
- **还是不行怎么办**：区分「网络问题」还是「模型名问题」——拉一个明显不存在的名字若立刻返回 `model not found`，说明网络通、问题在模型名；同样超时就是网络。可先用更小的视觉模型验证链路（`python tools\modelprobe.py` 看参数规模），或先只跑云端（见 4.7）。

> ⚠️ 用镜像/加速源时只选官方或你信任的地址；**`OLLAMA_MODELS` 只决定模型存哪，不加速下载**。

### 2.3 「已安装模型」里没有我配置的模型 / 下拉框读不出模型

- **现象**：自检「已安装模型」⚠️「当前配置的模型 xxx 不在列表里，请在设置里改选」；或设置里点「刷新模型列表」提示「没读到模型：请确认本地服务在运行（ollama serve），并且已经 ollama pull 过视觉模型」。
- **原因**：两种情况——① 服务在跑但一个模型都没有（自检直接给 ❌「本地服务在跑，但没有任何模型」，建议「执行：ollama pull qwen3-vl:4b（或 lms load qwen3-vl-4b-instruct）」）；② 有模型但名字对不上，`local.model` 必须与列表完全一致（含 tag，如 `qwen3-vl:4b` 不能写成 `qwen3-vl`），LM Studio 显示的 id 与下载文件名也可能不同。
- **解决办法**：
  1. 命令行核对并让工具帮你选：`ollama list`、`python tools\modelprobe.py`（会标出「⌾识图 / 纯文本」，当前模型打 ←当前）、`python tools\modelprobe.py --set qwen3-vl:4b`；
  2. 界面上：设置 → 本地模型 → **刷新模型列表** → 下拉框选择；或点 **测试连接**；
  3. 直接改配置后重启：`"local": { "model": "qwen3-vl:4b" }`。
- **还是不行怎么办**：用 `python tools\modelprobe.py --start` 先自动拉起服务再列模型，排除「服务没起来」的干扰；列表确实为空就回到 2.2 先把模型拉下来。

### 2.4 拉错了模型：纯文本模型不能识图（识图报错或结果为空）

- **现象**：本地识别失败，或结果为空（结果区提示「未识别出题目：…」）；日志里本地识别报错。
- **原因**：本地模型必须是**视觉模型**。`deepseek-r1`、`llama3` 这类纯文本模型收到图片会报错或直接忽略图片。本软件推荐并默认使用 `qwen3-vl:4b`（约 4.4B，4G 左右显存即可流畅运行）。
- **解决办法**：
  1. 看能力标注（按 `vl / vision / llava / minicpm-v / qwen2.5-vl / qwen3-vl / gemma3 / internvl` 判断，并调 `/api/show` 打印「能力：vision」）：`python tools\modelprobe.py`；单个模型用 `ollama show qwen3-vl:4b`；
  2. 换成视觉模型：`ollama pull qwen3-vl:4b` 后 `python tools\modelprobe.py --set qwen3-vl:4b`；
  3. 实测识图能力与速度（会造一张带中文与数学符号的测试图，分别在最长边 1200 / 1600 各跑一遍）：`python tools\modelprobe.py --vision`；
  4. 纯文本模型不是不能用，但**只能做错题分析**（本地分析只发题干文字、不发图），不能参与识别。
- **还是不行怎么办**：用云端验证是不是模型问题——左侧「待识别图片」页选中图片点 **云端重识别**（需先配好云端 Key，见 4.1）。云端能识别而本地不能，就锁定是本地模型能力问题。

> 💡 自检里的「本地模型视觉实测」同源：现场画一张写着「识别测试码：QINGHUA-7391」的图让模型读，读不对就给 ⚠️ 并建议「确认用的是视觉模型（如 qwen3-vl），或在设置里调大 max_image_side」。

### 2.5 显存不足 OOM / 模型加载失败

- **现象**：日志出现加载失败；整机卡顿、显卡驱动重置；识别中途报错。
- **原因**：4B 级视觉模型约占 4GB 显存，加上图片编码与上下文（`local.num_ctx` 默认 8192）会更高；同时开多个模型或同时跑游戏/浏览器更易 OOM。
- **解决办法**：
  1. **调小送模型最长边**：设置 → 本地模型 → **送模型最长边**（`local.max_image_side`，默认 1600；界面提示「显存紧张可调到 1100」）；
  2. 只留一个模型常驻并限制并行（改完重启 Ollama）：`set OLLAMA_MAX_LOADED_MODELS=1`、`set OLLAMA_NUM_PARALLEL=1`；
  3. 减小上下文与驻留时间（**界面没有入口**，改 `data/config.json` 后重启）：`"local": { "num_ctx": 4096, "keep_alive": "5m" }`；
  4. 识别时关掉视频/游戏；换参数量更小的视觉模型（用 `modelprobe` 看「参数」「量化」两列）。
- **还是不行怎么办**：临时把运行模式切到「云端优先」，或用更小的模型先把流程跑通，再导出一份诊断信息（第七章）确认到底是显存不足还是模型加载失败。

> 💡 识别本身是一张一张串行跑的（批量处理按顺序执行，`max_concurrency` 只是预留配置），所以「同时只处理一张」这件事不用你操心。

### 2.6 没有独立显卡，CPU 推理极慢

- **现象**：一张卷子要等好几分钟；自检「本地模型视觉实测」里 tok/s 很低。
- **原因**：视觉模型在 CPU 上就是慢，`local.timeout` 默认 300 秒（界面提示「CPU 跑视觉模型可能较慢，默认 300 秒」）正是为此留的余量；图片越大越慢。
- **解决办法**：
  1. 缩短送模型的最长边（对速度影响最大）：设置 → 本地模型 → **送模型最长边** 1600 → 1100；
  2. 确认 **关闭思考链（识别更快，qwen3-vl 建议开启）** 为勾选（`local.disable_thinking`，默认已开）；
  3. 加大超时别让慢被误判为失败：设置 → 本地模型 → **识别超时(秒)**（`local.timeout`）；
  4. 让云端干活：设置 → 运行模式 → **云端优先**（需 Key）；或保持「本地优先 + 云端兜底」但把 **置信度阈值** 调低（越小越少用云端）；
  5. 批量挂机用命令行：`python tools\import_cli.py "D:\照片\2026-03月考" --quiet`。
- **还是不行怎么办**：CPU 上「一张图 30 秒~3 分钟」属正常区间，不是卡死；「运行日志」页能看到每张图的 tokens、tok/s、用时，先看数字再决定是否换方案。确认 GPU 是否真的被用上：任务管理器 → 性能 → GPU 看显存占用。

### 2.7 模型/数据目录要挪到别的盘（`local.models_dir` / `local.home_dir` / `OLLAMA_MODELS`）

- **现象**：C 盘被模型占满；或 Ollama 装在受限目录，连模型列表都读不到。
- **原因**：三个键的含义——`local.models_dir`（设置：**模型目录**）＝Ollama 模型存放目录，多盘部署时填；`local.home_dir`（设置：**数据目录**）＝Ollama 的 `.ollama` 目录，受限环境时填；`local.server_exe`（设置：**服务程序路径**）＝`ollama.exe` 位置，留空自动查找。**只有程序自己拉起服务时**才会把它们作为环境变量传给子进程（`models_dir`→`OLLAMA_MODELS`，`home_dir`→`USERPROFILE`/`HOME`）；你自己在系统里启动的 Ollama 不受影响。
- **解决办法**：
  1. 先停服务再整目录搬（`blobs` 很大且是内容寻址文件，必须整体复制）：`taskkill /IM ollama.exe /F` 后 `robocopy "C:\Users\你\.ollama\models" "D:\ollama-models" /E /COPY:DAT /R:1 /W:1`；
  2. 两条路线二选一——**让程序管**：设置 → 本地模型 → 模型目录 `D:\ollama-models`、数据目录 `D:\ollama-home`，勾选自动拉起，重启软件；**让系统管**：`setx OLLAMA_MODELS "D:\ollama-models"` 并重启 Ollama，然后 `ollama list` 验证；
  3. 也可直接改配置后重启：`"local": { "models_dir": "D:\\ollama-models", "home_dir": "D:\\ollama-home" }`。
- **还是不行怎么办**：拷完 `ollama list` 为空说明 `blobs`/`manifests` 没搬全，重新整目录复制；确认目标卷是 NTFS（FAT32 单文件 4GB 限制会截断分片）。软件侧用 `python tools\modelprobe.py --start` 复验。

> ⚠️ 首次启动时程序会自动探测并把这三个值写进配置（搜程序目录、上一级、上上级，以及 `C:\Program Files\Ollama`、`%LOCALAPPDATA%\Programs\Ollama`）。若指到了你不想要的位置，手动改掉再保存。

### 2.8 模型输出里带思考过程或根本不是 JSON（软件如何容错）

- **现象**：日志出现「本地模型未按 JSON 输出，正在重试…」；结果字段缺漏；模型返回一段带推演过程的文字。
- **原因**：qwen3-vl 这类带思考链的模型**即使传 `think=false`，也可能把正式答案写进 `message.thinking` 而 `message.content` 为空**；小模型还爱输出 ```json 代码块、前后加废话、写尾逗号、把 JSON 截断。
- **解决办法**（软件已做的容错，知道就行）：
  1. **思考链兜底**：Ollama 分支统一「content 为空就用 thinking」，答案写在思考字段也能取到；
  2. **JSON 抽取**：依次尝试 ```json 代码块 → 括号配对截出的第一个对象（跳过字符串里的括号）→ 数组 → 整段原文；每一级都再试「原样 / 修复 / 修复+补全」三种解析（修复＝全角引号转半角、去尾逗号、去 `//` 与 `/* */` 注释、`None/True/False` 转小写；补全＝丢掉尾部残缺键值、补齐引号与括号）；
  3. **自动重试一次**：第一次没给出 JSON 时，追加「只输出 JSON 对象本身，第一个字符必须是 {」再压一次；
  4. 仍失败会记录「本地识别失败：…」，`hybrid` 模式下按配置自动转云端复核（见 3.5）。
- **还是不行怎么办**：确认设置里 **关闭思考链** 已勾选（默认 `true`）；换更听话的模型。想看模型原始输出，可把 `exerarchive\logging_setup.py` 里的 `setup()` 改成 `setup(level=logging.DEBUG)`（一行改动，仅排查用，查完改回）——日志文件默认只记 INFO 及以上，JSON 解析失败的原文是 DEBUG 级、默认不落盘。

## 三、识别类问题（8 条）

### 3.1 识别不准（手写潦草 / 反光 / 倾斜 / 模糊 / 多栏试卷）

- **现象**：题干缺字、答案认错、科目判错；日志与预处理页显示质量分偏低（如「图片质量分 0.28（清晰度 31，亮度 118）」）。
- **原因**：质量分是四项加权——清晰度 50% + 亮度 25% + 对比度 15% + 墨迹占比 10%。反光让对比度失真、倾斜让文字行错位、模糊让清晰度（拉普拉斯方差）不到 60、多栏排版让模型把两栏串成一行。
- **解决办法**：
  1. **先裁再识别**（多栏、带答案区的卷子最见效）：预处理页 → **✂ 裁剪（框选要保留的区域）** → **💾 保存处理结果（供识别/归档）** → 回到识别页点 **重新识别本张**；
  2. 一键优化：预处理页 **✨ 自动纠偏 / 提亮 / 锐化**（依次做去水印 → 纠偏 → 提亮/拉对比 → 轻度锐化 → 限制尺寸）；单独纠偏用 **🔍 自动检测倾斜并纠正**（小于 0.3° 会提示「没有检测到明显倾斜」）；
  3. 拍照习惯：正对纸面、光线均匀、避免闪光灯与台灯反光、卷面尽量占满画面、单栏拍摄；
  4. 让云端复核更多题：设置 → 运行模式 → **置信度阈值**（默认 0.70）调高到如 0.85，或把 **图片质量阈值**（默认 0.35）调高；
  5. 提高清晰度上限：设置 → 本地模型 → **送模型最长边**（默认 1600）调到 2000（更清晰但更慢更吃显存）。
- **还是不行怎么办**：对单张做「本地重识别 / 云端重识别」对比（左栏两个按钮），确定是模型能力还是图片质量问题。质量分一直低于 0.45 时程序和预处理页都会提示「建议云端复核」，此时直接走云端更省时间。

### 3.2 一页只识别出前几道题（单图题目数上限）

- **现象**：12 道题的卷子只出来 8 道。
- **原因**：`run.max_questions_per_image` 默认 **8**，它既写进提示词（「最多输出 {max_q} 道题」），又在结果归一化时二次截断——双保险防止小模型啰嗦。这是默认上限，不是 bug。
- **解决办法**：
  1. 设置 → 运行模式 → **单图最多题目数** 8 → 12（界面提示「防止模型在一张图上啰嗦太多（默认 8）」）；
  2. 或改配置后重启：`"run": { "max_questions_per_image": 12 }`；
  3. 题目特别多的一页，建议在预处理页裁成上下两张分别识别——题少时小模型准确率明显更高。
- **还是不行怎么办**：看日志里本地识别输出的 token 数，接近上限说明输出被截断，应拆图而不是继续加上限。**调到 20 以上不会更准**：上限越大越容易串题、漏状态。

### 3.3 题目对错状态判错了（错题判成正确题/未做题）

- **现象**：明明是错题，状态却是「未做题」或「正确题」；统计里的错题数不对。
- **原因**：状态判定规则写在提示词里（红笔打叉/批注 → `wrong`；红笔对勾或作答正确 → `correct`；该题位置空白、没有任何作答痕迹 → `blank`）。只有铅笔批改、老师只写个「查」、反光遮住红笔、错答案被擦掉重写、模型幻觉，都会误判。程序已有保护：模型给不出状态时是 `unknown`，流水线会**按「未做题」归档**并打上「状态是猜的」标记（宁可不冤枉成错题），归档目录也按状态分开。
- **解决办法**：
  1. 界面手动改（最直接）：左侧「题库」页选中题 → 右侧「识别结果」区 → **状态** 下拉框（`wrong` / `correct` / `blank`）→ **💾 保存修改**；
  2. 保存后会**同步重写归档文字稿**并把 `.md` 写到新状态对应的目录（旧目录的文件不会自动删除，需手工清理）；
  3. 让云端复核：选中题 → 「错题分析」页 → **☁ 云端深度分析**；识别阶段可调高 **置信度阈值** 让低置信度的题自动转云端（状态为 `unknown` 的题本身就会触发云端复核）。
- **还是不行怎么办**：批量错判通常是图片问题（红笔被反光/模糊吃掉），用预处理页的 **应用明暗**（亮度/对比度/伽马）提亮后重识别。一整片都是「未做题」时，注意这可能是 `unknown` 的统一兜底行为，需要人工核一遍状态。

### 3.4 学科 / 细分学科 / 学段 / 题型分类不合心意

- **现象**：物理题归到「数学」；大学题写成「高中」；解答题写成「简答题」。
- **原因**：这几项都是**固定枚举 + 归一化**：学科只能是 `数学/英语/物理/化学/生物/语文/其他`（「高数」「微积分」「线代」「math」等都归到「数学」）；题型只能是 `选择题/填空题/解答题/计算题/判断题/简答题/证明题/作文题/其他`；学段只能是 `小学/初中/高中/大学/其他`。归档目录就是按这几项拼的（`{subject}/{grade}/{qtype}/{status}`），改了分类归档路径也跟着变。
- **解决办法**：
  1. 界面手动改：左侧「题库」页选中题 → 右侧表单 **学科**（下拉）、**细分学科**（自由填，如「高等数学」）、**学段**（下拉）、**题型**（下拉）→ **💾 保存修改**；
  2. **知识点** 是自由文本，用顿号 `、` 或逗号分隔多个；**标签** 用右侧标签编辑器添加；
  3. 改完点 **🗂 归档选中** 重新归档，旧目录文件需手工删除；
  4. 改归档层级与命名：设置 → 归档 → **目录模板**（`{subject} {grade} {qtype} {status} {year} {month} {source}`）、**文件名模板**（`{uid} {status} {subject} {qtype}`）。
- **还是不行怎么办**：个别题手工改；一整批都错在同一项，多半是本地模型判断力不足——把 **置信度阈值** 调高让云端复核，云端在细分判断上更稳。提示词里的枚举值不在界面开放（避免把统计口径改乱），长期要改口径就改 `exerarchive\prompts.py` 的 `SUBJECTS` / `QTYPES` / `GRADES` 后重启。

### 3.5 识别结果为空（「没有识别出任何题目」）

- **现象**：结果区提示「未识别出题目：没有识别出任何题目」（后面可能跟模型报错原文）；待识别图片页该张状态显示「失败」。
- **原因**：① 图片本身有问题（空白页、只有页眉、糊到看不清、质量分极低）；② 本地模型不是视觉模型或服务不可用（返回「本地模型服务不可用」）；③ 模型返回了内容但没有可用题干——归一化会丢掉「题干、选项、作答」全空的条目；④ 错误信息的优先级是「云端错误 → 本地错误 → 没有识别出任何题目」。
- **解决办法**：
  1. 先确认图片能不能被正确解码：`python tools\selfcheck.py --no-model`；若「图像解码后端」是 ⚠️「纯Python（PNG/BMP）」，说明既没有 Pillow 也没有 GDI+，装一个会快很多：`pip install pillow`；
  2. 左栏选中该图 → **云端重识别**：云端能出结果＝本地模型问题（换视觉模型，见 2.4）；云端也空＝图片问题；
  3. 预处理页点 **重新检测** 看质量分，太低就 **✨ 自动纠偏 / 提亮 / 锐化** 后重识别；
  4. 若云端开着但配置不对（如没填 Key），云端错误会盖住本地错误——先按 4.1 修好，或临时把「☁ 云端增强」按钮关掉让本地结果暴露出来。
- **还是不行怎么办**：用「☁ 云端增强」开关做 A/B（关＝只看本地，开＝只看云端）；两次都为空就换 `samples\` 里的示例图验证程序本身正常。也可跑端到端验证核对标准答案：`python tools\verify_recognition.py`。

### 3.6 上传的图太大，识别很慢 / 很占显存

- **现象**：手机原图 4000×3000，识别一张要很久。
- **原因**：送模型前会按最长边压缩并重新 JPEG 编码，尺寸由 `local.max_image_side`（默认 1600）控制、画质由 `local.jpeg_quality`（默认 88）控制。**这两个键对云端同样生效**（云端也用同一套压缩参数）。
- **解决办法**：
  1. 设置 → 本地模型 → **送模型最长边** 调到 1100（界面原文「越小越快、越省显存（默认 1600；显存紧张可调到 1100）」）；
  2. 设置 → 本地模型 → **压缩画质** 调到 80（更小更快；低于 70 细笔画会发虚，不建议）；
  3. 预处理页裁剪后再识别（裁剪本身减少像素量）；
  4. 批量处理用命令行 `python tools\import_cli.py 目录 --quiet`，避免界面刷新干扰。
- **还是不行怎么办**：调小后反而识别不准，说明你的图字太小，需要「更大的图 + 更强模型 + 云端复核」，此时把最长边调回 1600 并调高置信度阈值走云端。这两个值随时可改、改完立即生效。

### 3.7 单张图里多道题被并成一道（或一道题被拆成两道）

- **现象**：结果只有一条记录，题干却是两道题连在一起；或一道大题被拆成两三条。
- **原因**：模型按视觉版式判断题目边界，遇到题号很小、排版紧凑、分栏、两题之间没有空行时容易串题。提示词要求按从上到下编号、一题一个元素，但小模型会失手。**界面上没有「拆题/合并」按钮**，所以只能靠裁图与改字段。
- **解决办法**：
  1. 裁图重识别（最稳）：预处理页 **✂ 裁剪** 只留一道题 → **💾 保存处理结果** → **重新识别本张**；
  2. 已有记录手工修正：右侧表单 **题干** 编辑框只留这一道题的内容 → **💾 保存修改**（会同步更新归档 `.md`）；
  3. 误拆出来的多余记录：左侧「题库」页选中 → **删除选中题**（二次确认；只删数据库记录与检索索引，已归档文件需自己清理）；
  4. 适当降低单图题目数上限（见 3.2）有时反而更准。
- **还是不行怎么办**：对多栏、多题的整页卷子，正确做法是「一张图一题」——用预处理页裁成多张，或干脆一次只拍一道题。指望本地 4B 模型稳定切分整页卷子不现实，云端复核能改善但不能保证。

### 3.8 附件答案页、草稿区被当成题目识别

- **现象**：结果里出现「参考答案：略」这类不是题目的条目；或草稿演算被当成题干。
- **原因**：模型看到页面上的文字就会尝试当题目处理，**答案页与题干页在同一张照片里**、或草稿纸和题目一起拍进去时最明显。
- **解决办法**：
  1. 裁掉无关区域：预处理页 **✂ 裁剪（框选要保留的区域）** 框掉答案区/草稿区 → **💾 保存处理结果（供识别/归档）** → 重新识别；
  2. 存量误识别记录：左侧「题库」页选中 → **删除选中题**；
  3. 水印/印章压住题目时用 **🧽 去水印（框选要抹掉的区域）**，三种方式可选——`inpaint`（四周插值，适合压住少量文字的印章）、`median`（局部平滑弱化，适合半透明水印压在文字上）、`white`（纸白覆盖，适合水印压在空白处）；
  4. 让云端复核：它收到的提示词明确要求复核题型与状态，对「这到底是不是一道题」判断更稳（调高置信度阈值或对单张点 **云端重识别**）。
- **还是不行怎么办**：「一页题目 + 一页答案」分开拍、分开导入；答案页不导入识别，需要时用「参考答案」字段手工补。程序没有「忽略某区域」的常驻配置，这一步只能靠裁图。

## 四、云端类问题（8 条）

### 4.1 API Key 填在哪里（三种方式，优先级从高到低）

- **现象**：不知道 Key 填哪；填了仍提示没配好。
- **原因**：云端要「总开关 + Key + Base URL + 模型名」四件齐备——`cloud_enabled()` 的判定是「勾选了启用云端增强」**且**当前档案里有 Key。
- **解决办法**：
  1. **界面（推荐）**：设置 → 云端模型 → 勾 **启用云端增强（填好 API Key 后勾选）** → 粘贴到 **API Key**（密文显示）→ 填对 **Base URL** 与 **模型名** → 点 **测试连接** 看到「云端连接正常 ✅」→ 保存；旁边还有 **获取模型列表**、**+ 新增 / 删除**（多套档案），顶部还有「☁ 云端增强：开/关」快捷开关；
  2. **环境变量**（配置文件留空时自动读取，顺序：`EXER_CLOUD_API_KEY` → `DEEPSEEK_API_KEY` → `OPENAI_API_KEY`）：`setx EXER_CLOUD_API_KEY "sk-你的Key"`，改完**重启软件**才生效；
  3. **配置文件**：`data/config.json` → `cloud.profiles[当前档案].api_key`（注意 JSON 转义，文件为 UTF-8）。
- **还是不行怎么办**：自检会直接告诉卡在哪一步——「云端增强」项要么是「未启用（当前：…）」，要么是「{档案名} 已启用但没填 API Key」，要么是「云端增强连通性」⚠️ 并附错误原文。

> ⚠️ `cloud.active` 是当前档案下标，`cloud.enabled` 是总开关；改完档案要保存，否则「正在编辑」的内容不会写回。

### 4.2 401 / 403 / 429 / 余额不足

- **现象**：点「测试连接」或识别时报 `HTTP 401：…`、`HTTP 403：…`、`HTTP 429：…`。
- **原因**：程序会把服务端返回的原文（前 400 字）拼成错误信息 `HTTP <状态码>：<服务端说明>`，**这句原文就是最准的线索**：401＝Key 缺失/写错/带引号空格；403＝无权访问该模型、未开通、地区或 IP 限制；429＝限流或额度耗尽；另有余额不足类提示。
- **解决办法**：
  1. 命令行绕开软件直接验 Key：`curl.exe -s -H "Authorization: Bearer sk-你的Key" https://api.deepseek.com/v1/models`——返回 JSON 列表＝Key 与 Base URL 都对，返回 401 就是 Key 问题；
  2. Key 粘贴时**不要**带引号与中文空格，重新粘贴后再点「测试连接」；
  3. 429/余额：稍等重试或到厂商控制台看额度（程序是串行调用、批量分析每 4 题一批，不会自己制造高频请求）；
  4. 换一套档案（设置 → 云端模型 → 配置档案 → **+ 新增**）先把流程跑通。
- **还是不行怎么办**：保留整行 `HTTP xxx：<原文>`（日志里也有），它通常直接写明原因（如 `insufficient balance`、`model not found`、`invalid api key`）；厂商侧问题只能换 Key 或换服务商。

### 4.3 云端请求超时、连不上

- **现象**：`URLError: <urlopen error timed out>` 或长时间无响应后失败；`HTTP 502/503/504`。
- **原因**：云端档案超时默认 180 秒（在档案字段里，界面未开放）；企业网络需代理，或服务端临时故障。
- **解决办法**：
  1. 先手工测通：`curl.exe -I https://api.deepseek.com/v1/models`；
  2. 需要代理时（Python 标准库会读取环境变量代理）：`setx HTTPS_PROXY "http://127.0.0.1:7890"`；
  3. 加大云端超时（**界面没有这项**，改配置后重启软件）：`"cloud": { "profiles": [ { "name": "DeepSeek（云端）", "timeout": 300, "max_tokens": 4096 } ] }`；
  4. 服务端 5xx 等几分钟再试；批量分析失败不影响已保存的本地识别结果。
- **还是不行怎么办**：把云端降级为「只做深度分析」（见 4.7），识别全走本地；或临时关掉「☁ 云端增强」按钮，保证识别流程可用。

> ⚠️ **只设 `HTTPS_PROXY`，不要设 `HTTP_PROXY`**：本地模型服务是 `http://127.0.0.1:11434`，一旦设了 `HTTP_PROXY`，本地请求也会被塞进代理而连不上。必须设时请在代理软件里放行 `127.0.0.1`。

### 4.4 Base URL 与模型名怎么核对

- **现象**：`HTTP 404：model not found`、`404 page not found`，或返回的 JSON 里没有 `choices`。
- **原因**：OpenAI 兼容分支拼 URL 的规则是——**Base URL 已以 `/chat/completions` 结尾就直接用；否则在它后面拼 `/chat/completions`；若只有域名没有路径则补成 `/v1/chat/completions`**。所以 `base_url` 一般填到 `/v1` 为止即可。
- **解决办法**：
  1. 界面上点 **获取模型列表**（请求 `{base_url}/models`，最多显示 20 个）：能列出模型名就说明 Base URL 正确，把名字复制到 **模型名**；部分服务不提供该接口，界面会提示「部分服务不提供 /models 接口，可手动填写模型名」；
  2. 命令行核对：`curl.exe -s -H "Authorization: Bearer sk-你的Key" https://api.deepseek.com/v1/models`；
  3. 典型填法（以厂商文档为准）：Base URL `https://api.deepseek.com/v1` + 模型名 `deepseek-chat`；Base URL `https://api.openai.com/v1` + 模型名 `gpt-4o-mini`；
  4. 别把整条 `.../v1/chat/completions` 塞进 Base URL 又额外拼一次（程序兼容但这种写法容易自己绕晕）。
- **还是不行怎么办**：自检「云端增强连通性」会打印 `{档案名} / {模型名}：正常` 或错误原文，先用它确认；再不行就用 curl 结果与厂商文档逐字比对模型名的大小写与连字符。

### 4.5 服务不支持 `response_format` 时软件会自动重试

- **现象**：日志里同一请求出现两次；第一次 `HTTP 400` 后仍然识别成功。
- **原因**：这是**设计好的自动降级**：请求 JSON 模式时会带 `response_format: {"type":"json_object"}`，若服务端返回 **400 或 422**，程序会去掉该字段**原样重试一次**（只对这两个状态码重试，其它错误不重试）。
- **解决办法**：
  1. 通常什么都不用做，等重试完成；
  2. 去掉后仍报 400，说明服务端不接受 payload 里的其它字段（如 `max_tokens` 名称差异），此时换模型或换服务商；
  3. 模型不支持强制 JSON 也能用：返回文本仍会走 JSON 容错解析（见 2.8）。
- **还是不行怎么办**：用「☁ 云端深度分析」看它能否给出结构化报告；长期失败就在设置里换一个明确支持 JSON 输出的模型。

### 4.6 纯文本云端模型不能发图（提示「只发送本地识别出的文字」）

- **现象**：日志出现「当前云端模型未开启视觉能力，只发送本地识别出的文字」；选「云端重识别」时云端似乎没看到图片。
- **原因**：云端档案里的 **该模型支持图片**（`supports_vision`）没勾，或隐私里关掉了图片上传——此时云端只收到文字，**图片在本地解析，隐私更好**。
- **解决办法**：
  1. 模型确实支持视觉（如 qwen-vl-max、glm-4v、gpt-4o 这类）→ 设置 → 云端模型 → 勾 **该模型支持图片** → 测试连接 → 保存；
  2. 模型是纯文本（如 `deepseek-chat`）→ 保持不勾，把它当「文字复核 + 深度分析」引擎，识别交给本地视觉模型；这也是默认档案 `DeepSeek（云端）` 的设定（`supports_vision: false`）；
  3. 检查隐私页 **允许把图片传给云端模型** 是否被关掉（见 4.8）。
- **还是不行怎么办**：想确认云端收到的是文字还是图片，看同一张图的两次调用日志：出现上面那句提示就是「只发文字」分支，没有就是「发图」分支。

### 4.7 云端用哪些能力最省钱

- **现象**：云端费用涨得快，想只把云端用在刀刃上。
- **原因**：云端有三处会被调用——① 识别兜底（可能发图，token 最贵）、② 错题深度分析、③ 批量分析（一次 4 题）。三处各有开关：**识别**是否允许联网由**运行模式**决定，**错题分析**是否走云端只看「云端是否启用 + 有没有 Key」（与运行模式无关，见下面的第 4 条）。
- **解决办法**（推荐组合：识别全本地 + 只让云端做错题分析）：
  1. 设置 → 运行模式 → **纯本地（完全离线，隐私最强）**：这是硬保证——兜底判定里显式排除了该模式（`mode != "local_only"`），即使「云端增强」开着、API Key 也填了，识别阶段**绝不会**发起云端调用；
  2. 「☁ 云端增强」开关的作用范围：它（配合当前档案里的 Key）构成「云端可用」的判定，决定 **`hybrid` 与 `cloud_first` 模式下允不允许用云端**——选 `cloud_first` 才会走「云端优先」直接交给云端识别，选 `hybrid` 才可能在低置信度/模糊时触发云端复核；关掉它，任何模式都不会调用云端识别；
  3. 于是「识别全本地 + 只让云端做深度分析」就是这么配的：运行模式选 **纯本地（完全离线）**，同时保持顶部「☁ 云端增强：开」并勾选 **错题分析使用云端深度版**（`run.cloud_for_analysis`）；不想让云端生成变式题就取消 **变式练习题由云端生成**（`run.cloud_for_variants`）；
  4. 想连错题分析也不联网：取消勾选 **错题分析使用云端深度版**，或直接关掉「☁ 云端增强」——本地分析失败还有**纯规则兜底报告**保证有结果；
  5. 仍在用 `hybrid` 时，把 **置信度阈值** 调低（界面原文「越小越少用云端」）如 0.70 → 0.55、把 **图片质量阈值** 调低，都能减少「低置信度/图糊就转云端」的次数；
  6. 自动分析只针对**错题**（`run.auto_analyze`），正确题与未做题不消耗额度；批量用 **🧠 生成错题分析** 比逐题点更省。
- **还是不行怎么办**：自查三处就能确认「纯本地」真的没联网——① 设置 → 运行模式的单选是否停在 **纯本地（完全离线）**；② 界面上的模式标签是否显示「纯本地（离线）」；③ `data\logs\app.log` 里没有任何云端调用记录（识别阶段不会出现「触发云端兜底：…」「云端识别」「云端识别失败」这些行）。平时看「运行日志」页的路由标记（`local` / `cloud` / `local→cloud`）与归档文字稿里的「识别引擎」，就知道钱花在哪一步。

> ✅ 已修正：现在的兜底判定是「云端可用 **且** `mode != "local_only"` **且** 结果是本地出的 **且** 模式不是云端优先」（源码注释：「纯本地模式绝不联网」）。**运行模式选「纯本地（完全离线）」时，识别阶段绝对不会调用云端**，与「云端增强」开关和 Key 是否存在无关；只有 `hybrid` / `cloud_first` 这两种模式才受「云端增强」开关的约束。

### 4.8 隐私开关：不想把图片传到云端（`privacy.send_image_to_cloud`）

- **现象**：想云端更准，但不想上传卷面照片。
- **原因**：设置 → 隐私与存储 有两个相关开关——**允许把图片传给云端模型**（`privacy.send_image_to_cloud`，界面原文「关掉后云端只收到本地识别出的文字；开启云端深度分析时更准。」）与**云端处理完删除本地原图（不推荐）**（`privacy.delete_local_after_cloud`，「开启后本地不再保留原图，无法回溯。」）。注意 `send_image_to_cloud` 与档案里的「该模型支持图片」是**与**关系，两者都开云端才会收到图片。
- **解决办法**：
  1. 关掉 **允许把图片传给云端模型** → 云端只收到文字；原图、预处理图、识别文本始终留存在本机 `data\` 里；
  2. 要彻底离线：运行模式选 **纯本地（完全离线）**（识别阶段保证不调用云端），再把顶部按钮切到「☁ 云端增强：关」（连错题深度分析也不走云端）——两者齐备时程序不会发起任何外部请求；
  3. 不建议打开「云端处理完删除本地原图」：开了本地不留原图，无法回溯也无法重新识别。
- **还是不行怎么办**：即使关了图片上传，识别兜底仍会把**文字**发给云端（题干里含卷面内容）；连文字都不能外发时只能保持云端增强关闭。数据库侧另有 **题库正文加密存储**（`privacy.encrypt_db`，默认开），见 6.5。

## 五、导出类问题（5 条）

### 5.1 导出的 PDF 文字不能选中 / 是图片版（浏览器未找到 → 内置渲染）

- **现象**：PDF 能看，但选不中文字、搜不到；文件比预期大。
- **原因**：PDF 导出有两条路径——① **优先**用系统自带 Edge/Chrome 的无头模式 `--headless=new --print-to-pdf` 打印 HTML（文字可选、体积小、排版好）；② 找不到浏览器时退回**自带生成器**：每页文字用 Windows GDI 渲染成位图后无损压缩（FlateDecode）塞进 PDF，题目原图按 JPEG（DCTDecode）嵌入，中文绝不会变方块，代价是**文字不可选中**。自检「PDF 导出（浏览器打印）」会显示「找到：<路径>」，找不到时给 ⚠️「不影响使用：会自动改用内置渲染器生成图片版 PDF（体积略大）」。
- **解决办法**：
  1. 想要可选文字：安装 Edge 或 Chrome（程序按这些位置查找：`%ProgramFiles%\Microsoft\Edge\Application\msedge.exe`、`%ProgramFiles(x86)%\...`、`%ProgramFiles%\Google\Chrome\Application\chrome.exe`、`%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`，以及 PATH 里的 `msedge/chrome/chromium/google-chrome`）；
  2. 浏览器装在非标准位置导致找不到时，装回默认位置，或接受图片版 PDF；
  3. 想要「文字可选 + 体积小」又不想装浏览器：导出 **网页（.html）** 或 **Word（.docx）**，需要 PDF 时自己打印一次；
  4. 非 Windows 且没找到浏览器时，内置渲染会直接报「当前系统不支持内置 PDF 渲染（需要 Windows GDI），请改用 HTML/Word 导出」——按第 3 条做。
- **还是不行怎么办**：先跑自检看那一项找到没有；路径存在但生成失败时日志会有「浏览器生成 PDF 失败：…」或「调用浏览器失败：…」，常见原因是浏览器首次运行需要初始化，手工打开一次浏览器再导出。

### 5.2 导出很慢 / 文件特别大

- **现象**：导出「全部题目 + 图片」等很久，产出的 PDF/Word 上百 MB。
- **原因**：导出会把图片一起打包——收集阶段把图缩到最长边 900 再按 JPEG 85 编码；内置渲染的 PDF 里每道题原图各占一整页，文字页以 2 倍分辨率渲染（约 144 DPI）；Word 里图片最宽 520px。题目越多、图越多越大。
- **解决办法**：
  1. 按需导出，别直接全量：**导出知识点薄弱清单…**（仅统计表 + 错题明细，很小）→ **导出错题汇总…**（统计 + 错题列表）→ **导出全部错题（个人错题本）…**（只含错题）→ **导出全部题目…**（最大）；
  2. 格式取舍：`.docx` 通常比内置渲染的 `.pdf` 小；`.html` 是单文件（图片可内嵌 base64），发手机方便；
  3. 导出在后台线程跑，界面不会卡死，日志会打印最终「（大小）」；先小范围试一次估量级。
- **还是不行怎么办**：先用 **导出全部数据 (JSON)** 做一次纯数据备份（不含图片、极快）；图片与归档文件本来就在 `data\` 里，不必再塞进 PDF 备份一遍。

### 5.3 Word 打开提示「文件格式与扩展名不一致 / 内容有问题」

- **现象**：`个人错题本_20260315.docx` 双击后 Word 要求修复，或提示内容有问题。
- **原因**：`.docx` 本质是 **zip + 一组 XML**，本软件用标准库 `zipfile` 手工组装标准 OOXML 包（`[Content_Types].xml`、`_rels/.rels`、`word/document.xml`、`word/styles.xml`、`word/_rels/document.xml.rels`，图片放 `word/media/`）。写出时是「先写 `.tmp` 再原子替换」，正常流程不会产生半截文件；打不开通常是：导出过程中程序被强杀或磁盘写满、目标文件被同步盘占用或替换中、杀软在落盘瞬间锁文件、阅读器太旧。
- **解决办法**：
  1. 重新导出到本地非同步目录（如 `D:\导出\`）再打开；
  2. 验证包结构完整（把后缀改成 `.zip` 用资源管理器打开，或命令行 `Copy-Item "D:\导出\个人错题本.docx" "$env:TEMP\check.zip"` 后 `Expand-Archive "$env:TEMP\check.zip" "$env:TEMP\check_docx" -Force`）——能列出 `[Content_Types].xml`、`word\document.xml`、`word\media\*` 就是结构完整的包，问题在阅读器侧；
  3. 换用 WPS 或较新版 Office；再不行改用 **HTML** 或 **Markdown** 导出（无包结构，任何编辑器都能看）；
  4. 确认磁盘空间与导出目录权限（见 5.5）。
- **还是不行怎么办**：同一批题分别导出 `.docx` 与 `.html`——HTML 正常而 Word 不正常，基本可判定是阅读器/环境问题，用 HTML 打印成 PDF 即可。

### 5.4 PDF / Word 里中文变成方块或乱码

- **现象**：内置渲染的 PDF 里中文是方块；或 Word 里中文显示异常。
- **原因**：内置渲染用 Windows GDI 画字，字体按 `SimHei → DengXian → Microsoft YaHei → SimSun → Arial` 取第一个可用的，**系统缺中文字体就会画成方块**；自检专门有「中文字体渲染」项（用 SimHei 渲染「中文渲染自检：错题本 123」并统计笔画像素），深色像素不足 300 就给 ⚠️「中文可能显示为方块」。Word 的字体在 `styles.xml` 里指定为 `Microsoft YaHei / 微软雅黑`，目标机器没有时由 Word 自行替换。
- **解决办法**：
  1. 安装中文字体：设置 → 时间和语言 → 语言 → 中文(简体) → 语言选项 → 可选字体功能；或直接安装 `simhei.ttf`、`msyh.ttc`；
  2. 验证：`python tools\selfcheck.py --no-model`，看「中文字体渲染」是否回到 ✅（会打印「SimHei 渲染出 N 个笔画像素」）；
  3. 用浏览器打印路径导出的 PDF 由浏览器渲染、字体更全，装 Edge/Chrome 即可（见 5.1）；
  4. 非 Windows 环境一律用 HTML / Word / Markdown 导出。
- **还是不行怎么办**：自检给的建议是「安装黑体/雅黑字体，或在设置里换字体」；**界面目前没有字体设置项**，界面字体可在 `data/config.json` 的 `ui.font_family` 修改（改完重启），而 PDF 用字由程序自动挑选、不受该项影响。

### 5.5 导出失败：目录没权限 / 文件被占用 / 路径太长

- **现象**：导出时报写入失败，或导出完成后找不到文件。
- **原因**：导出先写 `<目标文件>.tmp` 再原子替换，**目标目录必须可写**。常见触发：导出到 `C:\Program Files`、只读 U 盘、OneDrive 目录；目标文件正被 Word/PDF 阅读器打开；深层目录加长文件名超过路径限制。
- **解决办法**：
  1. 换到有写权限的短路径：`D:\导出\` 或程序自带的 `data\backup\`；
  2. 关掉正在打开该文件的 Word/PDF 阅读器再导出；
  3. 授权（管理员命令行）：`icacls "D:\导出" /grant "%USERNAME%":(OI)(CI)F /T`；
  4. 开启长路径支持（同 1.6 第 4 条）；
  5. 导出成功后状态栏显示「已导出：文件名（大小）」，日志里有完整路径，按它去开。
- **还是不行怎么办**：先导出体积最小的「知识点薄弱清单」到 `data\backup\` 验证导出功能本身正常，再逐步换目录/换格式定位问题。

## 六、数据类问题（6 条）

### 6.1 我的数据到底存在哪（`data\` 全量清单）

- **现象**：想手工备份/清理，但分不清哪些是数据、哪些是缓存。
- **原因**：程序是**绿色便携**设计，所有用户数据都在程序目录下的 `data\`（可用环境变量 `EXER_HOME` 覆盖根目录）。
- **解决办法**：对照下表，先认清哪些文件不能碰、哪些只是缓存。

| 路径 | 内容 | 删了会怎样 |
| --- | --- | --- |
| `data\archive.db` | SQLite 主库（图片、题目、报告、标签、检索索引） | 题目与报告全丢 |
| `data\archive.db-wal` / `-shm` | WAL 日志（库开着时存在） | 只能软件退出后删，开着删会损坏 |
| `data\master.key` | **加密主密钥（32 字节）** | 丢了旧密文永远读不出来（见 6.5） |
| `data\config.json` | 全部设置（含云端档案与 Key） | 恢复默认设置，题库不受影响 |
| `data\logs\app.log` | 运行日志（滚动，最多 3 个 1MB 备份） | 丢历史日志 |
| `data\images\导入_时间戳\` | 导入时复制的原图 | 原图丢失，无法重新识别 |
| `data\preprocessed\` | 预处理后的图（识别与归档用它） | 可重新生成 |
| `data\thumbs\` | 缩略图缓存 | 可重新生成 |
| `data\归档\` | 按「学科/学段/题型/状态」归档的原图 + 预处理图 + `.md` 文字稿 + 错题分析 | 归档成果丢失（数据库记录还在） |
| `data\backup\` | 备份 zip 与导出的 JSON | 备份丢失 |
| `data\tmp\` | 临时文件 | 可删 |
- **还是不行怎么办**：界面直接跳转去看——顶部 **更多 ▾ → 打开数据目录 / 打开归档目录 / 查看运行日志文件**；设置 → 关于 → **打开数据目录**（那里也显示配置与日志的完整路径）。显示的路径不符合预期时，检查是否设过 `EXER_HOME`：`echo %EXER_HOME%`。

### 6.2 换电脑、换硬盘、U 盘随身带：怎么迁移

- **现象**：要换机器，或想把整套东西搬到 D 盘。
- **原因**：程序把代码与 `data\` 放在一起，配置里存的都是相对路径，所以「整目录搬走」是最省事的迁移方式；而**只搬 `archive.db` 是不够的**。
- **解决办法**：
  1. **整目录拷贝（推荐）**：`robocopy "C:\deepseek\exercise-archive" "E:\exerarchive" /E /COPY:DAT /R:1 /W:1`，拷完在新位置双击 `启动.bat`；
  2. **只搬数据、代码另取**：把旧机 `data\` 整个复制到新机程序目录下（**必须包含 `master.key`**）；
  3. **数据放别的盘、代码原地不动**：`setx EXER_HOME "E:\exerarchive-data"`，再把 `data\` 整个移过去，重启软件（注意 `EXER_HOME` 也决定程序找 `samples\` 的位置）；
  4. 迁移前停掉软件（WAL 模式下运行中拷贝可能拷到不一致状态）。
- **还是不行怎么办**：迁移后跑一次自检，「数据目录可写」「加密模块自检」「数据库」三项都应是 ✅；再打开「题库」随机点两道题，确认题干与报告能看到。

> ⚠️ **只拷 `archive.db` 是最常见的错误**：没有 `master.key`，新机器上题干、作答、答案、错题报告全是空白；没有 `images\`，原图也没了。

### 6.3 怎么备份、怎么恢复

- **现象**：想定期备份，或换机后要把数据拿回来。
- **原因**：`store.backup_zip()` 会把整个 `data\` 打成 zip（自动跳过 `backup\` 目录本身，包含图片与归档）；另有 `export_json()` 导出解密后的 JSON，便于二次加工但**是明文**。
- **解决办法**：
  1. **备份**：顶部 **更多 ▾ → 备份数据（打包 zip）**，产物在 `data\backup\backup_年月日_时分秒.zip`，日志记录「备份完成：…（N 个文件）」；
  2. **导出 JSON**：**更多 ▾ → 导出全部数据 (JSON)** → `data\backup\export_年月日_时分秒.json`（正文已解密，不要随手发人）；
  3. **恢复**：**更多 ▾ → 从备份恢复…** → 选 zip → 确认「会用备份包覆盖当前数据库与图片」→ 完成后面板自动刷新；
  4. 手工备份/恢复等价做法：软件退出后 `robocopy "D:\exerarchive\data" "E:\备份\exerarchive-data" /E /COPY:DAT`；恢复时把内容复制/解压回程序目录下的 `data\`（保持相对路径）。
- **还是不行怎么办**：备份 zip 打不开时先用资源管理器看内容是否含 `archive.db` 与 `master.key`；恢复后界面没刷新就重启软件。**恢复是覆盖式的**，动手前先把当前 `data\` 复制一份。

### 6.4 怎么彻底清空数据

- **现象**：想重新开始，或要把机器交还/转手。
- **原因**：清空是分层的——数据库表与图片缓存会被清，归档成果、备份、设置、密钥不在这范围内。
- **解决办法**：
  1. 界面：**更多 ▾ → 清空全部数据…**，有两次确认（第二次是「真的要清空吗？这是最后一次确认。」）；
  2. 它做的事：清空 `search_index`、`reports`、`tags`、`questions`、`images` 五张表 → `VACUUM` 收缩 → 删除 `data\images\`、`data\preprocessed\`、`data\thumbs\` 的内容并重建空目录；
  3. **注意范围**：`data\归档\`（归档成果）、`data\backup\`（备份）、`data\logs\`（日志）、`data\config.json`（设置）、`data\master.key`（密钥）都**不在**清空范围内，需自行处理；
  4. 彻底清除（连密钥与设置一起，软件退出后执行）：`rmdir /S /Q "D:\exerarchive\data"`，下次启动会重建 `data\` 与一把新 `master.key`。
- **还是不行怎么办**：清空后统计看板还显示旧数字，点一下左侧页签或重启刷新；提示数据库被占用时先完全退出软件（任务管理器确认没有 python/pythonw 进程）。**执行第 4 步前务必确认备份已另存**——旧密文没有旧密钥就再也读不回来。

### 6.5 换机器后题目和报告变成空白（`master.key` 丢失的后果）

- **现象**：新机器上题库列表有题、状态与学科也在，但**题干、选项、我的作答、参考答案、错题报告全是空白**；`data\logs\app.log` 出现 `报告解密失败（Q20260918-0007）：校验失败：数据被篡改，或主密钥/口令不匹配`。
- **原因**：① 题库正文（题干/选项/学生作答/步骤/参考答案/错题报告）**加密存放**——ChaCha20 流加密 + HMAC-SHA256 完整性校验（先加密后认证），密钥用 PBKDF2-HMAC-SHA256 从「`data\master.key`（32 字节随机数）+ 可选口令」派生，每个值都有自己的随机 salt 与 nonce；② **密钥材料完全来自 `master.key`**，文件不存在时会**自动生成一把新的**；③ 于是只拷 `archive.db` 时新机器生成新密钥 → HMAC 校验失败 → 解密报「校验失败」，而 `decrypt_text` 遇错返回空字符串，所以界面**静默空白**、只在日志留痕；④ **本软件当前没有设置/修改口令的界面**（代码保留了口令参数与换口令的内部函数，但界面未开放，实际口令始终为空），所以这个版本里唯一能丢的就是 `master.key`；⑤ 学科、题型、状态、学段、知识点名称、置信度、文件名等**分类字段是明文**（要参与统计与建目录），所以这些还能看到。
- **解决办法**：
  1. **把 `master.key` 找回来**：从旧机器、U 盘或 `data\backup\*.zip`（备份打包了整个 `data\`，含它）取出，放回 `data\master.key`，重启软件即可读出全部旧数据——例如 `Expand-Archive "E:\备份\backup_20260315_120000.zip" "$env:TEMP\exbak" -Force` 后 `Copy-Item "$env:TEMP\exbak\master.key" "D:\exerarchive\data\master.key" -Force`；
  2. 恢复前先停软件，避免覆盖正在使用的密钥；
  3. 验证：重启后随机点几道题看题干是否出现，或 `python -c "from exerarchive.crypto import self_test; print(self_test())"`。
- **还是不行怎么办**：`master.key` 永久丢失且无任何备份时，**旧密文无法恢复**（加密算法的性质，不是 bug）——可依靠明文分类字段恢复统计与目录，但题干与报告必须重新识别或手工补录。因此请务必用「备份数据（打包 zip）」备份（它含 `master.key`），不要只拷 `archive.db`。若只是个别报告空白而题干正常，说明密钥没问题，是那份报告当时没生成成功，选中题目点 **🧠 生成错题分析** 重新生成即可。

### 6.6 搜索搜不到 / 单字搜索很慢（加密检索的原理与限制）

- **现象**：题库里明明有这道题，「全局搜索」却搜不到；或只输入一个字时界面卡一会儿。
- **原因**：正文加密后数据库里没有明文可供匹配，检索用的是**指纹索引**：写入题目/报告时把题干、选项、学生作答、参考答案、学生步骤、知识点、细分学科、题型（以及报告正文）切成**字符 2-gram 与 3-gram**，每个 n-gram 用 HMAC 算成不可逆短指纹存进 FTS5 表 `search_index`；查询时把关键词按同样规则算指纹匹配（长度 2 用 2-gram，≥3 用 3-gram），多个关键词以**空格**分隔且语义是 **AND**；指纹会误命中，所以**命中后还要逐条解密校验「关键词确实出现在正文里」**——因此不会给你假结果，但可能少给结果。**单字查询**（长度小于 2）无法用索引，会退回全表扫描（先取最多 3000 条候选再逐条解密），明显更慢。可搜范围含错题报告正文，**不含归档目录名与标签**。
- **解决办法**：
  1. 用 **2 个字以上**的关键词（如「行列式」「完形填空」「定积分」）；
  2. 多关键词用空格分隔，并确认它们**同时出现在同一道题**里：`导数 最值`；
  3. 考虑 OCR 错字（「幂」被认成「冪」、「∫」被认成「f」）：改掉题干错字后点 **💾 保存修改**（会重建该题的检索指纹）再搜；
  4. 按分类筛查走另一个入口：左侧 **题库** 页的 **状态**（`wrong/correct/blank`）与 **学科** 下拉筛选；
  5. 单字搜索尽量别用；一定要用就耐心等（全表扫描 + 逐条解密）。
- **还是不行怎么办**：所有关键词都搜不到时，先确认题库里确实有题（统计看板能看到题数）、且导入已保存完成。原理上的边界很清楚：这是「密文上的模糊检索」——靠 n-gram 召回 + 解密校验精确化，召回依赖关键词与正文的**字面重合度**，语义相近但用词不同的搜索搜不到。`data\test_store.db` 之类的测试库与主库无关，不影响搜索。

## 七、一键收集诊断信息

### 7.1 生成自检报告

```bat
cd /d C:\deepseek\exercise-archive

:: ✅ 推荐：让自检自己写文件（UTF-8，不受控制台编码影响）
python tools\selfcheck.py --out 诊断.json
python tools\selfcheck.py --no-model --out 诊断.json     :: 跳过模型实测，更快

:: 也可以打印到屏幕（--json），自己重定向；此时建议先切 UTF-8 代码页
chcp 65001
set PYTHONUTF8=1
python tools\selfcheck.py --json > 诊断.json
```

- `--out 文件` 是**最省心的写法**：程序直接以 UTF-8 写文件，cmd / PowerShell 的编码差异都不影响它；
- `--json` 输出结构：`app`、`version`、`generated_at`、`items[]`（每项含 `name`、`status`（✅/⚠️/❌）、`detail`、`hint`）、`failed`、`warned`、`ok`（无非 ❌ 项时为 `true`）；
- 退出码：**有 ❌ 返回 1，否则返回 0**，可直接用脚本判断；
- 不想用命令行：双击 `环境自检.bat`，或点界面右上角 **环境自检** 按钮（结果打到「运行日志」页签，不另开进程）。

> 💡 如果你坚持用 `>` 重定向：`cmd` 里输出被重定向后用的是系统本地编码（简体中文是 GBK），而自检报告里的 ✅/⚠️/❌ 不在 GBK 字符集内，会直接抛 `UnicodeEncodeError` 导致 `诊断.json` 为空——所以要 `chcp 65001` + `set PYTHONUTF8=1`。
> 另外 PowerShell 5.1 的 `>` 默认写 **UTF-16**，下游按 UTF-8 读会报 `invalid start byte`；用 `Out-File -Encoding utf8` 或干脆用 `--out`。

### 7.2 日志位置

- **`data\logs\app.log`**：主日志，写满 1MB 轮转，另有 `.1`、`.2`、`.3` 共 3 个备份；
- 界面 **「运行日志」页签**：实时面板（内存里最近 500 条），有 **清空显示** 与 **打开日志文件** 两个按钮；
- **更多 ▾ → 查看运行日志文件**：用系统默认程序直接打开日志文件。

日志通常已写明原因，例如：「本地模型服务未启动，且已关闭自动启动（设置里可打开）」「触发云端兜底：有 2 道题置信度低于 0.70（最低 0.42）」「当前云端模型未开启视觉能力，只发送本地识别出的文字」「报告解密失败（Q…）：校验失败…」。

> 💡 磁盘日志只记 **INFO 及以上**；模型 JSON 解析失败的原文是 DEBUG 级、默认不落盘（需要时见 2.8 最后一条）。

### 7.4 怎么自查 / 发给谁

1. **先自查**：打开 `诊断.json`，把所有 `"status": "❌"` 的项连同 `hint` 读一遍——自检的建议就是该失败项的处置办法；再看 `data\logs\app.log` 最后 50 行。
2. **按章对照**：「图形界面库 tkinter」❌ → 1.4；「数据目录可写 / 数据库」❌ → 1.8；「本地模型服务」❌ → 2.1；「已安装模型」⚠️ → 2.3；「本地模型视觉实测」⚠️ → 2.4 / 3.1；「云端增强」→ 第四章；「PDF 导出 / 中文字体渲染」→ 5.1 / 5.4。
3. **发给谁**：把 `诊断.json` + `data\logs\app.log`（有轮转文件就一起带）+ 7.3 的输出，交给维护者或帮你排查的同学，并附一句「在做什么操作时出的问题、期望什么结果、实际什么结果」。
4. **脱敏提醒**：`data\config.json` 里有 **API Key 明文**，要一起发就先把 `cloud.profiles[].api_key` 清空；`诊断.json` 只含检查项名称、状态与路径，**不含题干正文**，可放心发送；日志里可能出现**图片文件名与本地路径**（不含卷面内容），介意就把文件名涂掉；**不要**把 `data\master.key`、`data\archive.db` 发给任何人——拿到这两样等于拿到你全部题库内容。

## 附二：识别突然变慢 / 卡住不动（显卡被别的程序占了）

> 这是实测踩到的真实场景：软件本身没问题，是**显卡被别的程序抢走了**。

**现象**：昨天一页 3 道题只要 6~8 秒，今天同一张图转了 5 分钟还没出结果，最后报
`本地识别失败：TimeoutError: timed out`；或者日志里 `tok/s` 从 70~90 掉到个位数。

**原因**：本机视觉模型跑在显卡上。游戏（实测 `helldivers2.exe` 独占 GPU 时占用 90%、
显存 4.4 GB）、视频渲染、浏览器硬解视频、其他 AI 程序都会和它抢 GPU 与显存，
显存不够时 Ollama 还会把模型退回 CPU 推理，速度直接掉一个数量级。

**解决办法**：

1. **先看占用**：任务管理器 → 性能 → GPU，或执行 `nvidia-smi`；
   `python tools\selfcheck.py` 的「显卡（NVIDIA）」一项会直接报出
   占用率、显存用量与空闲量，占用 > 60% 或空闲显存 < 2.5 GB 时会给出 ⚠️ 警告。
2. **关掉抢资源的程序**（尤其是全屏游戏、渲染、视频会议），再重试。
3. **在软件里点一下「重新加载模型」**（v1.0.1 起）：
   设置 → 本地模型 → **「重新加载模型」**。它会卸载模型再按**当前空闲显存**重新加载，
   并回报前后比例（例如「上卡比例 11% → 100%」）。这一条是下面这个坑的正解。

> ⚠️ **关键坑（接管复核时实测）：光关掉别的程序还不够，必须让模型重新加载一次。**
> Ollama 是在**加载模型的那一刻**决定「多少层放显存、多少层留给 CPU」的，
> 之后**不会因为显存变空而重新规划**。所以「关掉游戏 → 直接重试」往往还是慢，
> 让人以为软件坏了。复核时实测的一组数字：
>
> | 状态 | 显存占用 | GPU 上的模型占比 | 实测速度 |
> | --- | --- | --- | --- |
> | 显存被占满时加载的模型 | 7815 / 8192 MB | 431 MB / 3.9 GB（约 11%） | **6.6 tok/s**（单图 47~130 秒） |
> | 清理占用 + 重新加载模型 | 2527 / 8192 MB | 全部 | **100 tok/s**（单图 5.4 秒） |
>
> 差了 **15 倍**，而两次跑的是同一份代码、同一张图。
>
> **怎么知道自己是这种情况**（三个地方都会告诉你）：
>
> | 在哪看 | 看到什么 |
> | --- | --- |
> | 自检「模型显存占用」项 | ⚠️ `qwen3-vl:4b 只有 11% 装在显存里（431 MB / 3.9 GB），识别会慢一个数量级` |
> | 识别时的运行日志 | `识别偏慢（6.6 tok/s）：…` + `↳ 建议：…`（每次运行只提示一次） |
> | 设置 → 本地模型 → 刷新模型列表 | 模型列表下面多一行显存占用结论（偏低时带 ⚠️） |
>
> **怎么修**（任选其一）：
>
> ```bat
> :: 方式一（推荐）：软件里点「设置 → 本地模型 → 重新加载模型」
>
> :: 方式二：命令行让 Ollama 立刻卸载该模型（下次识别时自动重新加载）
> curl.exe -X POST http://127.0.0.1:11434/api/generate -H "Content-Type: application/json" -d "{\"model\":\"qwen3-vl:4b\",\"keep_alive\":0}"
>
> :: 方式三：用 ollama 自带命令（等价）
> ollama stop qwen3-vl:4b
> ```
>
> 或者干脆在任务管理器里结束 `ollama.exe` 再启动软件（软件会自动拉起服务）。
> **怎么确认生效**：`ollama ps` 里的 `size_vram` 应该接近 `size`（3.9 GB 左右），
> 而不是只有十分之一；自检那一项会从 ⚠️ 变成 ✅。

> 💡 **显存被占，但看不出是谁占的？** 留意**上一次运行遗留的推理进程**：
> 任务管理器 →「详细信息」里若有多个 `llama-server.exe`，其中**启动时间比当前 `ollama.exe` 还早**
> 的就是残留（父进程已退出，它们却还在占显存）。复核时本机就积了 4 个，合计占掉 **5.3 GB**
> （清理后显存从 7815 MB 降到 2527 MB）。结束这些残留即可，下次识别会自动重新加载。
> 查看命令：`nvidia-smi --query-gpu=memory.used,memory.total --format=csv`。
4. **临时提速**：设置 → 本地模型 → 「送模型最长边」从 1600 调到 1100，
   「压缩画质」调到 80；单张图耗时通常能降 30%~50%。
5. **换更小的模型**：`qwen3-vl:2b` 之类，显存占用减半，代价是手写体准确率下降。
6. **切云端应急**：勾上「云端增强」并填好 Key，把运行模式改成「云端优先」，
   本地卡顿时直接交给云端（会产生 API 费用）。

**还是不行怎么办**：

- 确认显卡驱动正常（`nvidia-smi` 能正常输出、温度不过高、没有降到 PCIe 1x 之类）；
- 重启 Ollama 服务：结束 `ollama.exe` 进程后重新启动软件（软件会自动拉起服务）；
- 若模型被"卡死"（探活正常但一直不出字），多半是上一次请求被强行中断留下的状态，
  结束 `ollama.exe` 再重来即可（软件内的「停止」只会在当前图片处理完后生效，
  中断一个正在推理的请求要重启服务）。

> 💡 顺带一提：`local.timeout` 默认 300 秒。纯 CPU 跑 4B 视觉模型时确实可能需要几分钟，
> 所以默认给得比较宽；如果你确认机器够快，把它改小（例如 120）能更快暴露"卡住"的情况。

## 附三：启动软件时弹出一堆黑色命令行窗口（有的还残留）

> 这是实测抓到并已修复的问题，记录在此，方便你判断自己遇到的是不是同一种情况。

**现象**：双击快捷方式后冒出好几个黑色终端窗口（Windows 11 上是 Windows Terminal 窗口），
有的几秒后消失、有的一直留在任务栏；识别时又会再冒出一批。

**两个来源**（都实测复现过）：

| 来源 | 原因 | 现在怎么处理的 |
| --- | --- | --- |
| 双击 `启动.bat` | Windows 11 默认用 **Windows Terminal** 承载批处理窗口，而它经常不随脚本结束而关闭 | 桌面快捷方式**不再经过 bat**，改为直接调用 GUI 版解释器（`pyw -3 -m exerarchive`），完全不创建控制台窗口 |
| 识别时弹出的 `llama-server.exe` 窗口 | 自动拉起 `ollama serve` 时用了 `DETACHED_PROCESS`，ollama 因此没有控制台；它随后启动的推理子进程（控制台程序）就**各自新建一个可见控制台** —— 实测一次启动弹了 **15 个** | 改成只用 `CREATE_NO_WINDOW`（给 ollama 一个**隐藏**控制台，子进程继承它）。实测修复后加载模型前后新增窗口数为 **0** |

**你该怎么做**：

1. 用桌面的「AI 错题本」快捷方式启动（不要双击 `启动.bat`）；若快捷方式还是旧的，
   双击一次 `创建桌面快捷方式.bat` 重新生成（它会打印回读校验的目标路径，确认指向 `pyw.exe`）。
2. 若识别时仍弹窗口，说明本地模型服务是**旧参数**启动的：任务管理器里结束所有 `ollama.exe`，
   再重启软件（软件会用新参数重新拉起服务）。
3. 顺带一提：`环境自检.bat` / `一键验收.bat` / `运行全部测试.bat` 这些**双击时本来就该有窗口**
   （要给你看结果，末尾还有 `pause` 等你按键），属于正常现象。

> 💡 想自己确认：任务管理器 →「详细信息」看有没有一串 `WindowsTerminal.exe`；
> 这个软件正常运行期间**不应该有任何**这样的窗口。

## 附四：公式显示不对（显示成方块 / 还是纯文本 / 排版错乱）

**先自测**：双击 `环境自检.bat`，看「公式排版（数学渲染）」这一项。
正常会显示 `✅ 分式/根号/上下标/矩阵 4 类样例均正常`。

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| **公式太小 / 看着发虚发糊** | 早期版本按行高的 0.78 倍渲染，只有 13px 左右，且 GDI 小字号只有一档灰度抗锯齿 | 已改进：默认按行高的 **1.15 倍**渲染，并做 **3 倍超采样后缩回**（相当于每像素 9 个样本），笔画边缘干净很多。想更大/更小：`设置 → 界面与公式 → 公式大小倍率`（0.8~1.8，推荐 1.3~1.5）；想更清晰：`渲染精细度` 调到 4（公式特别多时才有速度差别） |
| 公式整段显示成**方块/空白** | 系统缺数学字体（软件按 `Cambria Math → Segoe UI Symbol → Consolas → 微软雅黑 → 宋体` 逐字回退，全都缺才会这样） | Windows 一般自带前两个；若是精简版系统，装一下 `Cambria Math`（随 Office 或 Windows 字体包）或 `Segoe UI Symbol` |
| 公式还是**纯文本**（`x^2`、`e^(2πik/6)`） | ① 报告是**旧版本软件**生成的（旧版提示词让模型输出简明写法）；② 报告是**本地规则版**（`rule`）兜底，本身不含 LaTeX | 在「错题分析」页点 `🧠 生成/更新分析` 重新生成一份即可（新提示词要求模型用标准 LaTeX 输出） |
| 报告页正常，**TXT 里是 `x^2` 这种** | 设计如此：TXT/Markdown 没法嵌图，会把 LaTeX 转成可读写法（`\frac{a}{b}` → `a/b`、`x^{2}` → `x²`、`\alpha` → `α`） | 想要图形排版就用 **HTML / Word / PDF** 导出（公式会作为图片内嵌，打印即教科书样式） |
| 上标里**多出空格**（`e^{2πi k/n}`）、`x=1` 挤在一起 | 遇到过（已修）：① 数学模式里源码空格被当成了真空格（LaTeX 里空格只是分隔符）；② 没有实现运算符的数学间距 | 已修：数学模式的空白一律忽略（`\text{...}` 里保留）；`=` `<` `>` `≤` `≥` 等关系符两侧留中等间距，`+ - × ÷` 等二元运算符留细间距，**一元负号**（`-b`、`x^{-1}`）不留间距。显式间距 `\,` `\;` `\quad` 照常生效 |
| 公式里出现**多余括号**（`e^(2πik/6)`、`x^(n-1)`） | 遇到过（已修）：识别模型有时按纯文本写法输出 `^(...)`，旧渲染器只把紧跟的那个左括号当成上标，于是变成"e + 悬空的上标 ( + 基线上的 2πik/6)" | 现在会自动规范化：`e^(2πik/6)` → `e^{2πik/6}`、`x^{(n-1)}` → `x^{n-1}`（去掉课本里不该有的外层括号）。**旧报告不用重新生成**，渲染时会实时规范化 |
| 导出文本里出现 `cosleft(...right)` 这种怪东西 | 遇到过（已修）：`\left` `\right` `\text` 这类排版命令被当成了字面单词 | 已修：这些命令会被正确吃掉（`\cos\left(\frac{k\pi}{3}\right)` → `cos(kπ/3)`、`\text{k}` → `k`）。若仍看到，说明是**旧版本导出的文件**，重新导出一次即可 |
| 矩阵/分式**位置错乱或重叠** | 遇到过（已修）：括号字号按字体行高反推会过大、数学字体的 ascent 是字号的 5 倍导致画到画面外 | 请更新到当前版本；若仍复现，把那段 LaTeX 发我，我按 `verify/math-preview.png` 的方式复现 |
| 想**自己看渲染效果** | — | 命令行运行 `python -m exerarchive.mathdraw verify/math-preview.png`，会生成一张包含分式/根号/矩阵/希腊字母的对照图；`verify/math-sharpness.png` 是"小字号 vs 超采样"的清晰度对比图 |

**为什么不用 MathJax / LaTeX？** 本工具要求**离线可用、零第三方依赖**：MathJax 要联网或额外打包 1MB 资源，
LaTeX 发行版动辄几百 MB。所以公式由软件自己用 Windows GDI 排版成图片（纯 ctypes 实现），
离线、免安装、和界面字体风格一致。
