# 05 · 模型与云端接口配置教程

> 面向对象：软件已经能打开、想**把识别调得更准更快**、或者想**接上云端强力模型**的用户。
> 本文对应需求文档里的两项交付：**「本地轻量化 AI 模型部署方案」** + **「云端 AI 通用接口适配方案」**。
>
> 前置：先跑通 `docs/01-安装部署教程.md`（软件能启动、`环境自检.bat` 没有失败项）。
> 本文所有**参数名、默认值、请求格式**都来自源码，可逐条对照：
> `exerarchive/config.py`（配置与默认值）、`exerarchive/vlm.py`（两套模型通道）、
> `exerarchive/prompts.py`（提示词）、`exerarchive/pipeline.py`（路由与兜底）、
> `exerarchive/analysis.py`（错题分析）、`exerarchive/ui/settingsdlg.py`（设置界面）、
> `tools/modelprobe.py`、`tools/selfcheck.py`。

**章节速览**：第 0 章看全部配置键 → 第一部分 1~4 章讲本地模型（选型/部署/调参/耗时）→ 第二部分 5~10 章讲云端接口（路由/服务对照/配置/成本隐私/排错/提示词）→ 第 11 章速查卡。

## 第 0 章 配置全貌（一张表看完所有键）

配置文件只有一份：**`data\config.json`**（界面上「设置」改的就是它；写回时是先写 `.tmp` 再原子替换，配置写坏时会留一份 `config.broken.json`）。

配置分五块：`run`（运行策略）、`local`（本地模型）、`cloud`（云端模型）、`ui`（界面）、`privacy`（隐私）、`archive`（归档）。

| 键 | 默认值 | 界面能改吗 | 说明 |
| --- | --- | --- | --- |
| `version` | `1` | — | 配置版本号 |
| `run.mode` | `hybrid` | ✅ 运行模式 | `local_only` / `hybrid` / `cloud_first`，非法值会被当成 `hybrid` |
| `run.confidence_threshold` | `0.70` | ✅ | 低于该置信度触发云端兜底 |
| `run.quality_threshold` | `0.35` | ✅ | 图片质量分低于该值直接转云端 |
| `run.cloud_on_error` | `true` | ✅ | 本地报错时自动转云端 |
| `run.cloud_for_analysis` | `true` | ✅ | 错题深度分析是否交云端（关掉=只用本地模型/规则） |
| `run.cloud_for_variants` | `true` | ✅ | 变式练习题是否交云端生成（见下方「保留键」说明） |
| `run.max_concurrency` | `1` | ❌ | 同时识别的图片数；**当前版本预留，实际按顺序串行处理** |
| `run.auto_preprocess` | `true` | ✅ | 导入后自动纠偏/提亮/锐化 |
| `run.auto_analyze` | `true` | ✅ | 识别出**错题**后自动生成分析报告 |
| `run.max_questions_per_image` | `8` | ✅ | 单张图最多切分几道题 |
| `local.kind` | `ollama` | ✅ 服务类型 | `ollama` / `lmstudio` / `openai_compatible` |
| `local.base_url` | `http://127.0.0.1:11434` | ✅ | 本地服务地址（LM Studio 常用 `http://127.0.0.1:1234`） |
| `local.model` | `qwen3-vl:4b` | ✅ 模型名称 | 本地视觉模型名 |
| `local.timeout` | `300` | ✅ | 单次请求超时（秒），CPU 跑要留足 |
| `local.num_ctx` | `8192` | ❌ 只能手改 | Ollama `options.num_ctx` |
| `local.temperature` | `0.1` | ❌ 只能手改 | 越低越稳定（识别任务必须低） |
| `local.max_image_side` | `1600` | ✅ 送模型最长边 | 送模型前的最长边；**云端发图也用这个值** |
| `local.jpeg_quality` | `88` | ✅ 压缩画质 | 送模型前 JPEG 质量；**云端发图也用这个值** |
| `local.auto_start` | `true` | ✅ | 启动软件时自动拉起本地服务 |
| `local.server_exe` | `""` | ✅ 服务程序路径 | 留空则自动查找并回写 |
| `local.models_dir` | `""` | ✅ 模型目录 | 自动拉起服务时会作为 `OLLAMA_MODELS` 传给子进程 |
| `local.home_dir` | `""` | ✅ 数据目录 | 自动拉起服务时会作为 `USERPROFILE` / `HOME` 传给子进程 |
| `local.keep_alive` | `"10m"` | ❌ 只能手改 | 模型在显存里常驻多久 |
| `local.disable_thinking` | `true` | ✅ 关闭思考链 | 勾选=不思考（更快）；代码里 `think = not disable_thinking` |
| `cloud.active` | `0` | ✅ 配置档案 | 当前使用的档案下标（0 起） |
| `cloud.enabled` | `false` | ✅ 云端增强 | **总开关**，界面上是顶部「☁ 云端增强：开/关」按钮（闸的是 `hybrid` / `cloud_first` 两种模式的云端调用；`local_only` 模式识别阶段本来就不走云端） |
| `cloud.cache_last_result` | `true` | ❌ | **保留键**：当前代码路径未使用它做缓存 |
| `cloud.profiles[]` | 见下 | ✅ | 多套云端档案，每套含 `name/base_url/model/api_key/supports_vision/timeout/max_tokens/temperature` |
| `ui.*` | 见下方 | ❌ 只能手改 | `theme=light`、`font_family=微软雅黑`、`font_size=10`、`thumb_size=180`、`window`（窗口位置，软件自动写）、`show_log_panel=false`、`image_display_max=1200` |
| `privacy.encrypt_db` | `true` | ✅ | 题干/作答/报告在数据库里加密存放 |
| `privacy.send_image_to_cloud` | `true` | ✅ | 允许把（压缩后的）图片传云端；关掉则只传文字 |
| `privacy.delete_local_after_cloud` | `false` | ✅ | **保留键**：当前代码路径没有执行「云端处理完删本地原图」的动作 |
| `archive.root` | `""` | ✅ | 留空 = `data\归档` |
| `archive.pattern` | `{subject}/{grade}/{qtype}/{status}` | ✅ | 目录层级模板 |
| `archive.write_text` | `true` | ✅ | 同步写 `.md` 文字版 |
| `archive.write_report` | `true` | ✅ | 错题报告写入归档 |
| `archive.copy_original` | `true` | ✅ | 归档时复制原图 |
| `archive.naming` | `{uid}_{status}` | ✅ | 文件名模板 |

云端出厂的两套档案（`cloud.profiles`，字段顺序与原文件一致）：

```json
[{"name": "DeepSeek（云端）", "base_url": "https://api.deepseek.com/v1", "model": "deepseek-chat",
  "api_key": "", "supports_vision": false, "timeout": 180, "max_tokens": 4096, "temperature": 0.3},
 {"name": "任意 OpenAI 兼容（可填通义/智谱/Kimi/本地大模型）", "base_url": "https://api.openai.com/v1",
  "model": "gpt-4o-mini", "api_key": "", "supports_vision": true, "timeout": 180, "max_tokens": 4096,
  "temperature": 0.3}]
```

> 💡 **「保留键」是什么意思**：这几个键能存进配置、界面上也有勾选框，但当前版本的代码路径里**没有实际读取它做判断/动作**（`run.cloud_for_variants` 只被界面读写；变式题由「执行分析的那个引擎」在同一个 JSON 里一并返回）。本文只讲真实生效的行为，不替代码许愿。
> 💡 **代码里还读了 5 个「隐藏开关」**（不在默认配置、界面也没有，但从配置里写就能生效，缺省都是 `true`）：`run.auto_skew`、`run.auto_brighten`、`run.auto_sharpen`（控制预处理里的纠偏/提亮/锐化）、`run.fallback_on_low_confidence`（低置信度是否兜底）、`run.fallback_on_blur`（模糊/低质量是否兜底）。另有 `local.api_key`：给需要鉴权的本地 OpenAI 兼容服务用（LM Studio 一般不需要）。

# 第一部分 本地轻量化模型部署方案

## 1. 模型选型对比

### 1.1 本机已部署的默认方案（推荐照抄）

| 项目 | 实际值 | 来源 |
| --- | --- | --- |
| 模型名 | `qwen3-vl:4b` | `ollama list` / `/api/tags` 实测 |
| 参数量 | **4.4B** | `/api/tags` → `details.parameter_size` |
| 量化 | **Q4_K_M**（GGUF） | `/api/tags` → `details.quantization_level` |
| 磁盘占用 | **3295636135 字节 ≈ 3.3 GB** | 模型 blob 实测 |
| 上下文长度 | 262144（`embedding_length` 2560） | `/api/tags` 元数据 |
| 能力标签 | `vision`、`completion`、`tools`、`thinking` | `/api/tags` → `capabilities` |
| 中文/手写体表现 | 印刷体、手写对勾/打叉/批注、行列式与积分符号均能读对 | `samples\recognition_report.json`（6 张样张，题数与对错状态 14/14 命中） |
| 速度（RTX 3070 8G） | **65–105 tok/s（典型约 85 tok/s）** | 本机 `lm-bench\测试报告.md` 实测 |
| 一页 3 题的端到端耗时 | **5.7–8.0 秒**（含预处理） | `recognition_report.json` 六张样张实测 |

### 1.2 可选模型对比（同一套软件都能用）

| 模型（Ollama 标签） | 体积 / 量化 | 显存需求 | 速度量级 | 中文 & 手写体 | 下载命令 | 适用机型 |
| --- | --- | --- | --- | --- | --- | --- |
| **`qwen3-vl:4b`**（默认，✅实测） | 约 3.3 GB / Q4_K_M | 识图峰值约 **6.0–7.0 GiB**（权重 2374 MiB + KV 2304 MiB@16K + 视觉编码器最坏 1355 MiB） | 65–105 tok/s（实测） | 好：中文印刷体+手写批注+数学符号，未见明显幻觉 | `ollama pull qwen3-vl:4b` | **8G 独显甜点**；6G 独显可跑（把 `max_image_side` 调到 1100） |
| `qwen3-vl:2b` | 约 1.9 GB | 约 3–4 GiB（估算） | 约为 4B 的 2 倍（估算） | 一般：小字、表格、潦草手写会掉 | `ollama pull qwen3-vl:2b` | **4G 独显 / 核显 / 老机器** |
| `qwen3-vl:8b` | 约 6.1 GB（权重） | 需 ≥12 GB 显存（8G 卡叠加 KV+视觉编码器会溢出） | 约为 4B 的 0.5 倍（估算） | 更好：复杂版式、长题干更稳 | `ollama pull qwen3-vl:8b` | **12G/16G 及以上独显** |
| `minicpm-v` | 约 5.5 GB（以官方页面为准） | 约 8–9 GiB（估算） | 低于 4B（估算） | 中文 OCR 口碑好，手写与理科公式一般 | `ollama pull minicpm-v` | 8G 独显可试，速度不如 4B |
| `llava:7b` | 约 4.7 GB（以官方页面为准） | 约 7–8 GiB（估算） | 与 8B 同级（估算） | **弱**：中文和手写体是短板，主要面向英文图文 | `ollama pull llava:7b` | 不建议中文习题场景，仅作兼容备选 |
| LM Studio：`Qwen3-VL-4B-Instruct-GGUF`（✅实测） | 语言 2381.6 MB + 视觉编码器 432.9 MB | 峰值 **5103–5168 MiB**（实测） | 38–72 tok/s（实测），加载约 8 秒 | 与本机 Ollama 同款模型，表现一致 | LM Studio 里搜模型名下载（见 2.2） | 喜欢图形界面的用户 |

> ⚠️ 上表中标了「估算」的行是**按参数量/显存带宽的比例推断**，没有在本机逐项实测；标「实测」的数字来自本机 RTX 3070 8G（见第 4 章）。
> 任何表的体积数字都可能随官方重新量化而变化，**以 <https://ollama.com/library> 对应模型页面显示为准**。
> 想验证某个模型在你机器上的真实速度，用 `python tools\modelprobe.py --vision`（第 2.4 节）。

### 1.3 按显存怎么选（结论先给）

| 你的机器 | 推荐 | 关键设置 |
| --- | --- | --- |
| 8G 独显（RTX 3060/3070、4060 等） | `qwen3-vl:4b` | 保持默认：`max_image_side=1600`、`num_ctx=8192`、`disable_thinking=true` |
| 6G 独显 | `qwen3-vl:4b`（优先）或 `qwen3-vl:2b` | `max_image_side` → `1100`；`num_ctx` → `4096` |
| 4G 独显 / 核显（共享内存） | `qwen3-vl:2b` | `max_image_side` → `1100`；一次只跑一张图 |
| 纯 CPU（无独显） | `qwen3-vl:2b` 或 `qwen3-vl:4b` | `timeout` → `600`；`max_image_side` → `1100`；接受每页 30 秒~2 分钟的等待 |
| 12G+ 独显 | `qwen3-vl:8b` | 其余默认即可 |

> 💡 **模型名字里必须有 `VL`**（Vision-Language）。`qwen3:4b`、`qwen2.5:7b` 这类是纯文本模型，**看不了图片**。
> 软件的探测工具就是按关键词判断的：`vl`、`vision`、`llava`、`minicpm-v`、`qwen2.5-vl`、`qwen3-vl`、`gemma3`、`internvl`
> （`tools/modelprobe.py` 里的 `VISION_HINTS`），不含这些关键词的模型会被标成「纯文本」。

## 2. 部署步骤

### 2.1 路线 A：Ollama（默认路线）

**第 1 步：安装。**

| 步骤 | 操作 |
| --- | --- |
| 下载 | 打开 <https://ollama.com/download>，点 **Download for Windows**（macOS 下载 macOS 版；另有 Linux 版） |
| 安装 | 双击安装包一路下一步，默认装到 `C:\Program Files\Ollama\`，并**开机自动在后台运行** |
| 验证 | 打开 `cmd`（或 PowerShell）执行 `ollama --version`，本机实测版本 **0.34.0** |

**第 2 步：拉取模型（约 3.3 GB）。**

```bat
ollama pull qwen3-vl:4b
ollama list
```

```bash
ollama pull qwen3-vl:4b
ollama list
```

`ollama list` 能看到 `qwen3-vl:4b` 就成功了。视网速几分钟到几十分钟，进度条滚动属正常。

**第 3 步：手动启动服务（通常不用做）。**

```bat
ollama serve
```

```bash
ollama serve
```

默认监听 `127.0.0.1:11434`。软件会在需要时自动拉起它（见 2.3），所以这一步只是排错手段。
想确认模型是不是正躺在显存里，可以看 `ollama ps`。

**第 4 步：把模型目录 / 数据目录挪到别的盘（可选，多盘部署常用）。**

Ollama 用两个环境变量决定文件放哪，**软件的「本地模型」页就是往这两个变量上写**：

| 环境变量 | 含义 | 软件里对应的配置键 | 软件的行为 |
| --- | --- | --- | --- |
| `OLLAMA_MODELS` | 模型文件（blobs/manifests）存放目录 | `local.models_dir` | 自动拉起 `ollama serve` 时注入到子进程环境 |
| `USERPROFILE` / `HOME` | Ollama 的 `.ollama` 数据/密钥目录所在的家目录 | `local.home_dir` | 同上，启动服务时把 `USERPROFILE` 和 `HOME` 都指向它 |

手动启动时（不通过软件）这么写（macOS/Linux 把 `set` 换成 `export`，或写进 shell 配置）：

```bat
set OLLAMA_MODELS=D:\ollama-models
set USERPROFILE=D:\ollama-home
ollama serve
```

**换端口（可选）**：Ollama 侧用 `OLLAMA_HOST`，然后用软件里的地址跟着改。

```bat
set OLLAMA_HOST=127.0.0.1:11435
ollama serve
```

| 侧 | 怎么改 | 注意 |
| --- | --- | --- |
| Ollama | 环境变量 `OLLAMA_HOST=127.0.0.1:11435` | 只影响 Ollama 自己监听哪个端口 |
| 软件 | 设置 → 本地模型 → **服务地址** 改成 `http://127.0.0.1:11435` | 软件不读 `OLLAMA_HOST`，**只认 `local.base_url`**，两边必须一致 |

> ⚠️ **本机实际部署示例**（可对照自己的情况）：
> 程序 `C:\deepseek\ollama\ollama.exe`（便携版，0.34.0）、模型目录 `C:\deepseek\ollama-models`、
> 数据目录 `C:\deepseek\ollama-home`、模型 `qwen3-vl:4b`；
> 对应配置：`"kind": "ollama"`、`"base_url": "http://127.0.0.1:11434"`、`"server_exe": "C:\\deepseek\\ollama\\ollama.exe"`、
> `"models_dir": "C:\\deepseek\\ollama-models"`、`"home_dir": "C:\\deepseek\\ollama-home"`。

| 步骤 | 操作 |

### 2.3 软件内置的「自动探测」与「自动启动」

**探测（首次运行/配置留空时自动完成，并写回配置）**——`config.default_ollama_paths()` 的真实顺序：

| 找什么 | 顺序 |
| --- | --- |
| `ollama.exe` | ① 程序目录 / 上一级 / 上上级目录下的 `ollama\ollama.exe` → ② 这三个目录下的 `ollama.exe` → ③ `C:\Program Files\Ollama\ollama.exe` → ④ `%USERPROFILE%\AppData\Local\Programs\Ollama\ollama.exe` → ⑤ 系统 PATH 里的 `ollama` |
| 模型目录 | ① 上述三个目录下的 `ollama-models` 或 `models`（**要求里面含 `manifests` 或 `blobs` 子目录**）→ ② `~\.ollama\models` |
| 数据目录 | ① 上述三个目录下的 `ollama-home`（要求里面含 `.ollama`）→ ② 家目录（含 `.ollama` 时） |

写回策略：只有 `local.server_exe` / `local.models_dir` / `local.home_dir` **为空**时才写入，写完立即保存；你在界面上手填过就不会被覆盖。

**自动启动**——`LocalServerManager.ensure_running()` 的真实行为：

| 行为 | 细节 |
| --- | --- |
| 先探活 | `ollama`：先探测端口是否可连，再请求 `/api/version`；`lmstudio`/`openai_compatible`：请求 `{地址}/models`（地址路径若不以 `/v1` 结尾会自动补成 `/v1/models`；配了 `local.api_key` 就带 `Bearer`） |
| 已开着 | 直接用，不做任何事 |
| 没开着 | 读 `local.auto_start`（默认开）→ 找 `local.server_exe`（找不到就现场再探测一次并写回配置）→ 执行 **`ollama serve`**；Windows 下带 `DETACHED_PROCESS \| CREATE_NO_WINDOW` 标志，**不弹黑窗口** |

| `--vision` | **实测识图**：现场用 GDI+ 画一张含中文/英文/数学符号的测试图，分别在**最长边 1200px 和 1600px** 下各跑一次，打印 **耗时、输出 tokens、tok/s** 与模型原始输出，并检查它有没有把「打叉=做错」判对 |

## 3. 关键参数调优表

以下每一项都可在 **设置 → 本地模型 / 运行模式** 里改（只标了「仅配置文件」的才需要手改 `data\config.json`）。

| 参数（默认值） | 作用 | 调大的后果 | 调小的后果 | 推荐值 | 什么时候该改 |
| --- | --- | --- | --- | --- | --- |
| `local.max_image_side`（`1600`） | 送模型前把图片最长边限制到这个值；**预处理缩放和云端发图也都用它**。实测 1600 → 缩成 1131×1600 | 更清晰、小字更准；显存与耗时同步上升（视觉 token 变多） | 更快更省显存；**小字号/密排版会看不清**，识别率明显下降 | 8G 卡 `1600`；6G/核显 `1100` | 报显存不足、或一页要等太久 → 降到 1100；小字老读错且显存有余 → 升到 2000 试 |
| `local.jpeg_quality`（`88`） | 编码成 JPEG 的质量（编码后以 `data:image/jpeg;base64,...` 发出） | 体积变大、传输变慢，识别率提升有限 | 体积小、上传快；低于 70 后笔画边缘发糊 | `88`；手机流量/慢网可 `80` | 云端按流量计费或网络很慢时降到 80 |
| `local.timeout`（`300` 秒） | 单次请求超时（本地识别用） | 慢机器不容易被误判超时 | 快机器上出错能更快报出来 | 独显 `300`；纯 CPU `600` | 日志出现超时/读秒中断 → 调大（CPU 尤其） |
| `local.num_ctx`（`8192`，仅配置文件） | Ollama 的 `options.num_ctx`，上下文长度 | 能塞更长的提示词与更多图片 token；显存占用上升（16K 时 KV 缓存实测 2304 MiB） | 省显存；超长回答可能被截断 | `8192`；本机实测 8192 与 16384 速度基本持平，显存够也可用 16384 | 6G 以下显存 → 降到 `4096` |
| `local.temperature`（`0.1`，仅配置文件） | 采样随机性 | 输出更"活泼"，**识别任务会开始编内容** | 更死板但更稳定 | `0.1`，识别任务不建议超过 `0.3` | 想让模型少说废话 → 保持 0.1 甚至 0 |
| `local.disable_thinking`（`true`） | 勾选=请求里带 `think:false`，不让模型先"想"一遍 | 取消勾选（即允许思考）：可能更准，但**明显更慢、输出更长** | —（默认就是关思考） | 保持勾选 | 难题、多步计算题识别不准时，可临时取消勾选对比 |
| `local.keep_alive`（`"10m"`，仅配置文件） | 请求级参数，告诉 Ollama 模型在显存里保留多久 | 更久不卸载，连续识别无重载成本 | 很快卸载，下一张图要重新加载（实测重载 30–68 秒） | `10m`；批量整理时可用 `-1` 常驻 | 隔一会儿识别一次就卡很久 → 改成 `-1`（一直常驻） |
| `run.max_questions_per_image`（`8`） | ① 写进识别提示词的「最多输出 N 道题」；② 解析时超出部分直接截断 | 一张大卷子（10 题以上）不会被砍；小模型更容易串题、啰嗦 | 一页多题时会漏题 | `8`；整页试卷用 `12`~`15` | 一页卷子被识别少了几题 → 调大；模型老是把相邻题混成一道 → 调小 |
| `run.confidence_threshold`（`0.70`） | 判定「要不要请云端复核」：**任意一道题**的 `confidence` 低于它就触发（每题置信度由模型给出，>1 时按百分比折算，最终裁剪到 0~1） | 更容易转云端（更准、更费钱） | 更少用云端（省钱） | 有 Key `0.70`；不想花钱填 Key 就无所谓 | 云端调用太频繁 → 降到 `0.5`；错题老是判错 → 升到 `0.85` |
| `run.quality_threshold`（`0.35`） | 图片质量分（`0.5×清晰度 + 0.25×亮度 + 0.15×对比度 + 0.10×墨迹占比`）低于它就**直接转云端**；另外**清晰度 < 40 也会触发**（这个 40 写死在代码里，不是配置项） | 质量稍微差一点就上云（更费钱） | 模糊照片也硬走本地 | `0.35` | 手机拍的照片经常模糊 → 升到 `0.5` 让它更早上云；没有 Key 时该值不产生任何云端调用 |
| `run.auto_preprocess`（`true`） | 导入后自动做：去水印（若手动框过）→ 纠偏（≥0.6° 才转）→ 提亮+对比度拉伸 → 轻度锐化（清晰度<90 才做）→ 缩放至 `max_image_side` | —（只能开/关） | 关掉后用原图识别：省一点时间，但歪的、暗的照片识别率会明显下降 | 保持开启 | 想排查"是不是预处理把字搞坏了" → 临时关掉对比 |

**顺手补充的几条经验值：**

| 现象 | 先动哪个参数 |
| --- | --- |
| 显存不足 / 报 OOM | `local.max_image_side` ↓、`local.num_ctx` ↓、换 `qwen3-vl:2b` |
| 一页等太久 | `local.max_image_side` ↓ 到 1100、确认 `local.disable_thinking` 是勾选状态、`local.keep_alive` 设 `-1` |
| 小字/公式读错 | `local.max_image_side` ↑ 到 1800~2000、换更大的模型 |
| 模型把两道题混成一道 | `run.max_questions_per_image` ↓ 到 5~6，或先在编辑器里裁图 |
| 认不出对错（全是"未做题"） | 检查是不是下了纯文本模型；再看 `run.quality_threshold` 与照片清晰度 |

# 第二部分 云端强力模型接入（OpenAI 兼容通用适配）

## 5. 什么时候会自动转云端

软件的云端通道是**通用 OpenAI 兼容适配**：只要对方提供 `/chat/completions` 风格接口，填对 Base URL + 模型名 + Key 就能用。
不接云端时，软件**不会报错**，全部走本地。

### 5.1 前置条件：`cloud_usable()`

云端识别（兜底 / 云端优先 / 云端重识别）必须**同时**满足两个条件：

| 条件 | 配置键 | 说明 |
| --- | --- | --- |
| ① 云端增强总开关 = 开 | `cloud.enabled` | 顶部「☁ 云端增强：开/关」按钮或设置里勾选 |
| ② 当前档案有可用 Key | `cloud.profiles[cloud.active].api_key` 或环境变量 | Key 为空时回落到 `EXER_CLOUD_API_KEY` → `DEEPSEEK_API_KEY` → `OPENAI_API_KEY` |
| ③ 运行模式允许云端（仅"自动兜底"看这一条） | `run.mode` | 只有 `hybrid` 会做自动兜底；`local_only` **永不兜底**；`cloud_first` 是直接整张图走云端，不走兜底（见 5.2） |

不满足时：与云端有关的那段逻辑整段跳过，结果就是纯本地，**不会弹错**（这正是 `docs/01` 里说的"没填 Key 自动退化成纯本地"）。想把这段逻辑彻底关在门外，直接把运行模式选成「纯本地（完全离线）」（见 5.2）。

### 5.2 `pipeline._need_cloud()` 的真实判定（逐条翻译）

只有在 `hybrid`（本地优先 + 云端兜底）模式下，本地识别跑完后才会**按顺序**评估下面这些条件，命中任意一条就转云端复核；`local_only` 与 `cloud_first` 都不会走到这里（原因见 5.2 末尾的说明）：

| 序 | 代码里的条件 | 中文含义 | 日志里会看到 | 受哪个开关控制 |
| --- | --- | --- | --- | --- |
| ① | `local_res is None or not local_res.ok` | **本地识别报错/没跑成**（服务不可用、超时、返回空） | `触发云端兜底：本地识别失败（HTTP 500：…）` | `run.cloud_on_error`（隐藏键，默认 `true`；关掉则本条件下不兜底） |
| ② | `not questions` | **本地一道题都没识别出来** | `触发云端兜底：本地没有识别出题目` | 无开关，必定触发 |
| ③ | 存在 `confidence < thr` 的题 | **有题置信度低于阈值**（阈值 `run.confidence_threshold`，默认 0.70） | `触发云端兜底：有 2 道题置信度低于 0.70（最低 0.55）` | `run.fallback_on_low_confidence`（隐藏键，默认 `true`） |
| ④ | 存在 `status == "unknown"` 的题 | **有题无法判定对/错/空白状态** | `触发云端兜底：有 1 道题无法判定对错状态` | 无开关，必定触发 |
| ⑤ | `quality.score < qthr` | **图片质量分偏低**（阈值 `run.quality_threshold`，默认 0.35） | `触发云端兜底：图片质量分偏低（0.28 < 0.35）` | `run.fallback_on_blur`（隐藏键，默认 `true`） |
| ⑥ | `quality.sharpness < 40` | **图片偏模糊**（清晰度低于 40，写死在代码里） | `触发云端兜底：图片偏模糊（清晰度 31）` | `run.fallback_on_blur` |

云端兜底用的是**复核提示词**：会把本地识别结果 JSON（截断到 6000 字符）连同图片一起发过去，让云端「只修正错误项，尽量保留本地已识别的题干」。

再加三条**执行条件**（在上面判定之外）：

| 条件 | 说明 |
| --- | --- |
| `mode != "cloud_first"` | 云端优先模式不会再走一遍兜底（它本来就是云端跑的） |
| `mode != "local_only"` | **纯本地模式下兜底整段跳过**，识别阶段绝不会调用云端 |
| `cloud_usable()` | 见 5.1；不满足则整段跳过 |

> ✅ **硬保证（已修正）：`local_only`（纯本地、完全离线）模式下，识别阶段绝对不会调用云端。**
> 兜底判定的完整表达式：`cloud_usable() and mode != "local_only" and out.route in ("local", "") and mode != "cloud_first"`。
> 其中 `mode != "local_only"` 这条**与「云端增强」开关、与有没有 Key 都无关**：只要运行模式是「纯本地（完全离线）」，
> 即使总开关开着、Key 也填好了，本地失败 / 无题目 / 状态未判定 / 低置信度 / 模糊这六种情况**一个都不会触发云端**
> （`local_only` 只做本地识别，失败就在界面上报「没有识别出任何题目」）——**断网也能放心用，不会偷偷出网**。
> 💡 `cloud.enabled`（顶部「☁ 云端增强」）只约束 `hybrid` / `cloud_first` 两种模式（这两种模式下它是硬前提：关掉就等于没有云端）；`local_only` 下它开或关都不影响识别阶段，因为识别阶段根本不会走到云端那段代码。唯一例外：错题分析页的「☁ 云端深度分析」是**手动**发起的单题分析，不看模式也不看总开关，只要求当前档案有 Key（见 5.3、8.1）。

### 5.3 怎么手动强制云端

| 方式 | 操作位置 | 实际行为 |
| --- | --- | --- |
| ① 全程云端优先 | 设置 → 运行模式 → **云端优先**（`run.mode = "cloud_first"`） | 每张图直接走云端识别；**云端失败会自动回落到本地**（日志：「云端识别未成功…，转本地」） |
| ② 单图云端重识别 | 左侧「待识别图片」选中一张 → **「云端重识别」**按钮 | 对这张图强制走云端（内部 `force="cloud"`），不影响其它图；旁边的「本地重识别」是 `force="local"` |
| ③ 单题云端深度分析 | 错题分析页 → **「☁ 云端深度分析」** | `allow_cloud=True`，**无条件尝试云端**：它不检查「云端增强」总开关，只要当前档案有 Key 就会发起请求；失败会保留本地报告并打日志 |
| ④ 批量分析走云端 | 工具栏「🧠 生成错题分析」 | 按 `run.cloud_for_analysis` 与 `cloud_usable()` 自动决定（都满足才用云端） |
| ⑤ 总开关 | 顶部「☁ 云端增强：开/关」 | 没有 Key 时会先问你要不要去设置里填；它约束的是 `hybrid` / `cloud_first` 两种模式的云端调用（`local_only` 模式识别阶段根本不会评估云端兜底） |

### 5.4 界面上 `route` 字段的含义

识别完成后，界面/日志里会出现路由标记，实际只会是这三个值：

| `route` | 含义 |
| --- | --- |
| `local` | 只用本地模型（含云端优先模式失败后回落本地的情况） |
| `cloud` | 只用云端（云端优先模式且成功） |
| `local→cloud` | 本地识别完成后触发了云端复核（5.2 里 ①~⑥ 任一条），最终结果以云端为主、本地补缺 |

合并规则：云端题干过短（不足本地的 60%）时取信息量更大的那个；云端缺的知识点、状态为 `unknown` 的，用本地的补上。
本地判定为「未判定」的题最终会**按未做题归档并打上 `status_guessed` 标记**（避免被误当成错题要求分析）。

## 6. 通用配置四要素与 6 家服务对照表

### 6.1 四要素：填对这 4 个就能用

| 要素 | 配置键 | 界面对应 | 代码里怎么用 | 填错的典型症状 |
| --- | --- | --- | --- | --- |
| **Base URL** | `cloud.profiles[i].base_url` | 「Base URL」输入框 | 拆成 origin + path，再拼 `/chat/completions`（见 6.2） | HTTP 404 / 连接超时 |
| **模型名** | `cloud.profiles[i].model` | 「模型名」输入框 | 放进请求体 `"model"` | HTTP 404（"model not found"）/ 400 |
| **API Key** | `cloud.profiles[i].api_key` | 「API Key」输入框（密码样式） | 作为请求头 `Authorization: Bearer <Key>` | HTTP 401 / 403 |
| **是否支持图片** | `cloud.profiles[i].supports_vision` | 「该模型支持图片」勾选框 | 勾选=内容里带 `image_url`（`data:image/jpeg;base64,…`）；不勾=**只发文字** | 勾错：纯文本模型收到图片 → 400/422；不勾却想让它看图 → 它只能瞎猜 |

另外两个**只能在 `data\config.json` 里改**的档案参数（界面没有输入框）：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `timeout` | `180` | 云端单次请求超时（秒）。长报告写不完时调大 |
| `max_tokens` | `4096` | 请求体 `max_tokens`（留空/删掉则不发这个字段）。想省钱可以调到 `1500`~`2000` |
| `temperature` | `0.3` | 云端采样温度。识别任务建议 0.1~0.3；深度分析 0.3~0.5 |

### 6.2 Base URL 到底要不要带 `/v1`？（三种写法都能用）

代码的拼接规则（`vlm._call_openai`）：先把 Base URL 拆成 `origin + path`，然后
- 如果 `path` 以 `/chat/completions` 结尾 → **原样使用**；
- 否则 → `origin + path + "/chat/completions"`；
- 如果完全没写 path → `origin + "/v1/chat/completions"`。

| 你填的 Base URL | 实际请求的地址 | 结论 |
| --- | --- | --- |
| `https://api.deepseek.com/v1` | `https://api.deepseek.com/v1/chat/completions` | ✅ 推荐写法 |
| `https://api.deepseek.com` | `https://api.deepseek.com/v1/chat/completions` | ✅ 也能用（自动补 `/v1`） |
| `https://api.deepseek.com/v1/chat/completions` | 原样使用 | ✅ 也能用 |
| `https://open.bigmodel.cn/api/paas/v4` | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | ✅ 智谱这种**不带 `/v1`** 的路径同样正确 |

> ⚠️ 反过来不成立：**不要把 `/v1` 重复写两遍**（如 `.../v1/v1`），代码不会帮你纠正，服务端会 404。
> 结尾多一个 `/` 无所谓（内部会先去掉尾部斜杠）。

### 7.3 API Key 的三种放法与环境变量优先级

| 放法 | 写法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| ① 界面里填 | 设置 → 云端模型 → API Key → 保存 | 最简单 | **明文存在 `data\config.json` 里**（拷走配置文件=拷走 Key） |
| ② 手改配置 | `"api_key": "sk-..."` | 同上 | 同上 |
| ③ 环境变量 | `set EXER_CLOUD_API_KEY=sk-...` | 不落盘、换机器只改环境 | 需要在启动软件的同一个环境里设置 |

优先级（**代码里的真实顺序**）：

1. 当前档案的 `api_key`（非空就用它）；
2. 为空时才依次尝试环境变量：**`EXER_CLOUD_API_KEY` → `DEEPSEEK_API_KEY` → `OPENAI_API_KEY`**（第一个非空的胜出）。

```bat
set EXER_CLOUD_API_KEY=sk-xxxxxxxx
set DEEPSEEK_API_KEY=sk-yyyyyyyy
```

```powershell
$env:EXER_CLOUD_API_KEY = "sk-xxxxxxxx"
```

> ⚠️ 用 DeepSeek 时也可以只设 `DEEPSEEK_API_KEY`；用 OpenAI 时只设 `OPENAI_API_KEY`。
> 但**别指望"环境变量的 Key 会覆盖配置里填错的 Key"**——配置里非空就优先用配置里的，写错了要先清空它。

## 8. 成本与隐私控制

### 8.1 什么时候发图片、什么时候只发文字

代码里的判定是**两个开关同时为真才发图**：`supports_vision`（这套档案的模型能不能看图）**且** `privacy.send_image_to_cloud`（全局是否允许外发图片）。

| `supports_vision` | `send_image_to_cloud` | 识别阶段（兜底/云端优先/重识别） | 深度分析阶段 |
| --- | --- | --- | --- |
| ✅ 勾选 | ✅ 允许 | **发图**（压缩到 `local.max_image_side` / `local.jpeg_quality`，格式 `data:image/jpeg;base64,…`） | **发图** + 发文字（归因更准） |
| ✅ 勾选 | ❌ 不允许 | 只发文字：识别提示词里写着"识别这张图"，但**图没发出去**，通常返回空/无效题目 → 结果仍用本地识别 | 只发文字（题目 JSON + 本地初版分析） |
| ❌ 不勾选 | 任意 | 只发文字（同上） | 只发文字 |
| ❌ 不勾选 | — | 日志会写：`当前云端模型未开启视觉能力，只发送本地识别出的文字` | 同上 |

> ⚠️ **结论要记牢**：关掉 `send_image_to_cloud` **不能**让云端"省着看图识别"，只会让云端识别失效，
> 它真正的作用是**给深度分析省图片、保隐私**。识别要出网就得发图（或者干脆别让它出网）。

### 8.2 只想用云端做「错题分析」、识别永远本地的省钱组合（推荐）

**做法：填好 Key，但把「云端增强」总开关关掉。**

| 配置 | 值 | 为什么 |
| --- | --- | --- |
| `cloud.enabled` | `false`（顶部按钮显示"关"） | `cloud_usable()` 为假 → **识别阶段 100% 不调云端**（`hybrid` / `cloud_first` 也一样不调）；另外 `local_only` 模式本身就保证识别阶段不联网。批量/自动分析也会走本地 |
| `cloud.profiles[active].api_key` | 填上（或设环境变量） | 错题分析页的「☁ 云端深度分析」按钮**不检查总开关**，有 Key 就能用 |
| `cloud.profiles[active].supports_vision` | `false`（用 DeepSeek/Kimi 这类文本模型） | 分析时只发文字，token 最省、隐私最好 |
| `privacy.send_image_to_cloud` | `false` | 双保险：即使换了支持视觉的模型也不会把图发出去 |
| `run.auto_analyze` | `true` | 识别出错题后自动生成**本地**报告（秒出、免费） |
| `max_tokens` | `1500`~`2500` | 报告够用，账单更小（要手改 `config.json`） |

用法就一句话：**平时让软件离线跑；对某道错题想要更深的分析时，选中它 → 点「☁ 云端深度分析」。**

### 8.3 token 消耗量级（估算，用来心里有数）

| 场景 | 输入量级 | 输出量级 | 依据 / 备注 |
| --- | --- | --- | --- |
| 本地识图一页（Ollama） | 约 2340 tokens（视觉编码） | 200–400 tokens | **实测**：视觉编码约 750 ms，`modelprobe --vision` 输出 241–281 tokens |
| 云端识图一页（按图片计费的服务） | 图片 token（各家算法不同，常见几百~2000+）+ 提示词约 300 tokens | 200–600 tokens | **估算**；分辨率越高越贵，所以 `local.max_image_side` 也直接影响云端账单 |
| 云端深度分析一题 | 题目 JSON（≤5000 字符）+ 本地初版分析（≤3000 字符）+ 模板约 800 tokens ≈ **2k–4k tokens** | 1k–2k tokens | 代码里对 payload 做了截断；上限受 `max_tokens`（默认 4096）约束 |
| 云端批量分析 | **一次请求分析 4 道题**（`chunk_size = 4`），payload 截断 9000 字符 | 每批约 2k–4k tokens | 批量比逐题省：模板只算一次 |

> ⚠️ 上表是**量级估算**，不是精确账单。精确数字看：① 各家控制台的用量统计；② 软件日志里云端调用会打印**输出 tokens 与耗时**
> （`云端识别 320 tokens，用时 6.2s`）——注意软件只记录输出 token，输入 token 得看服务商后台。

## 9. 自检与排错

### 9.1 自检与验证入口

| 获取模型列表 | 设置 → 云端模型 → **「获取模型列表」** | `GET {Base URL}/models`（带 Bearer），20 秒超时，列前 20 个 id |
| 识别质量回归 | `python tools\verify_recognition.py` | 拿 `samples\` 6 张样张跑完整流水线，和 `ground_truth.json` 对答案，结果写 `samples\recognition_report.json` |
| 本地后端适配（不需要显卡） | `python tools\verify_local_backends.py` | 起假 Ollama + 假 OpenAI 服务，验证 Ollama 协议细节（裸 base64 图片 / `options` / `think` / `format`、答案落在 `thinking` 时的回退、非 JSON 时自动重试）、LM Studio 与 `openai_compatible` 路线、以及**纯本地模式下云端收不到任何请求** |
| 云端通道适配（不需要 Key） | `python tools\verify_cloud.py` | 起本地假 OpenAI 服务，真实 HTTP 验证认证头、Base URL 三种写法、请求体结构、`response_format` 被拒时自动重试、500 处理、cloud_first 端到端与 hybrid 兜底 |
| 全部一起跑（不需要显卡） | `一键验收.bat` | 上面这些 + 125 项单元测试 + 导出验证 + 全流程闭环 + 界面截图，7 步全自动 |

### 9.2 常见错误码与处置

云端失败时软件**不会崩溃**：会记一条日志（`云端识别失败：HTTP 401：…`），识别结果自动保留本地版本。

| 现象 / 日志 | 最可能的原因 | 处置 |
| --- | --- | --- |
| `HTTP 401：…` | Key 错、没填、多了空格、用了别家的 Key | 重新复制 Key；确认「测试连接」通过；注意 DeepSeek 的 Key 不能拿去调通义 |
| `HTTP 403：…` | Key 无该模型权限、未实名/未开通、地区限制 | 到厂商控制台开通对应模型；查余额与实名状态 |
| `HTTP 404：…` | **Base URL 或模型名写错**（最常见） | 用「获取模型列表」核对；智谱是 `/api/paas/v4` 不是 `/v1`；别把 `/v1` 写两遍 |
| `HTTP 400` / `HTTP 422` | 请求体被拒：不支持 `response_format`、`max_tokens` 超限、给纯文本模型发了图 | 软件见 400/422 会**自动去掉 `response_format` 重试一次**；仍失败就：取消「该模型支持图片」、把 `max_tokens` 调小或删掉 |
| `HTTP 429：…` | 触发限流，或余额不足 | 等一会儿再试；到控制台看额度/欠费；本软件云端调用本身是串行的（批量分析一次 4 题），不会自己打满配额 |
| 超时 / `timed out` / `TimeoutError` | 网络不通、Base URL 不通、代理拦截、服务太慢 | 先用 `curl` 试那个地址；把 `profiles[].timeout` 从 180 调大；公司网络/代理环境下换网络 |
| `云端返回缺少 choices：…` | 对方**不是** OpenAI 兼容格式（或返回了错误结构） | 换成官方 OpenAI 兼容地址；OneAPI 网关里确认渠道类型 |
| `模型返回空内容` | 模型把内容放进了 reasoning/thinking 字段，或纯文本模型被要求看图 | 换对话模型（如 `deepseek-chat`）；确认 `supports_vision` 勾选正确 |
| 云端识别成功但"题数比本地少" | 复核提示词被截断（本地结果截到 6000 字符） | 属于正常现象：软件会**用本地补缺**（题干过短时取本地的） |
| 「☁ 云端深度分析」点完没反应 | 只在日志里写了 `云端分析未成功（HTTP 401…），保留本地报告` | 这个按钮**不检查总开关**：Key 不对就会失败；填对 Key 或环境变量即可 |

## 10. 提示词自定义

提示词全在 **`exerarchive/prompts.py`**，一共 8 个常量和 4 个归一化函数。改它不需要动其它模块，但要**知道改了会影响哪里**。

| 常量 | 用在哪 | 你可以改它来做什么 |
| --- | --- | --- |
| `SUBJECTS` | 识别/云端识别提示词、归一化、界面学科筛选 | 增删学科大类（**归档目录和统计都依赖它**） |
| `QTYPES` | 同上 | 增删题型（如加"实验题""翻译题"） |
| `STATUSES` / `STATUS_CN` | 状态取值与中文名 | 只有当你要新增状态（例如"半对"）时才改，且必须同步改 `normalize_status`、`pipeline`、`archive`、统计 |
| `GRADES` | 学段取值 | 增删学段 |
| `SUBJECT_DETAIL_EXAMPLES` | 只做提示词里的举例参考（帮助模型写对细分学科） | 换成你常考的分支，识别更贴你的教材 |
| `RECOGNIZE_SYSTEM` | **本地 + 云端识别共用**的系统提示 | 改语气/加约束（例如"数学符号统一写成 LaTeX"） |
| `RECOGNIZE_PROMPT` | 本地识别主提示词（含 JSON 字段模板 + 7 条判定规则） | **改识别字段、改对错判定口径、改示例**（最常改的就是这个） |
| `RECOGNIZE_RETRY_PROMPT` | 本地第一次没输出合法 JSON 时的"再压一次"补丁 | 一般不用改 |
| `ANALYZE_SYSTEM` / `ANALYZE_PROMPT` | 错题报告（本地与云端共用） | **改报告深度**：要求几步解法、要不要给口诀、变式题数量 |
| `ANALYZE_BATCH_PROMPT` | 云端批量分析（一次 4 题，输出 `{"reports":[{...}]}`） | 改批量报告的字段 |
| `CLOUD_RECOGNIZE_PROMPT` | 云端首次识别时的精简版提示词 | 让云端识别更详细/更简短 |
| `CLOUD_VERIFY_PROMPT` | 云端**复核本地结果**时用（带本地 JSON + 修正要求） | 改"重点复核什么"的措辞 |
| `normalize_subject / _status / _qtype / _grade` | 把模型输出的杂七杂八写法归一成固定枚举 | 模型总把某个学科/题型写错时，在这里加别名映射最省事 |

**为什么这么设计（读懂这 4 条就不会改坏）：**

1. **强制 JSON**：小模型容易"话痨"，模板里反复强调只输出 JSON、字段名固定，解析层还有容错（`vlm.extract_json` 能处理代码块、前后废话、尾逗号、被截断的 JSON）。
2. **枚举写死**：学科/题型/状态/学段都是固定中文取值，**归档目录名与统计全靠它们**（`archive.pattern` 里的 `{status}` 会变成"错题/正确题/未做题"）。
3. **留空而不是编造**：明确要求"看不清就填 `?`、不确定就填空字符串"，宁可让置信度低的题被路由到云端复核，也不要小模型幻觉出错误答案。
4. **少样本**：给了一个 1 题的完整示例，小模型照抄格式的准确率明显更高——**改字段时一定要同步改示例**，否则模型会照旧输出。

### 10.1 小例子：改成"只识别题干，不判对错"

**① 打开 `exerarchive/prompts.py`，在 `RECOGNIZE_PROMPT` 里做两处改动：**

```python
# 改动一：输出模板里删掉 "status" 这一行（示例 JSON 里同样删掉）
# 改动二：原第 4 条判定规则（wrong/correct/blank 三选一）整条删除，后面的规则依次补位，
#         并补一条"不要判断对错"的约束（下例即重新编号后的规则 1、4、5、6）
RECOGNIZE_PROMPT = """请识别这张习题图片，并把结果**严格**输出为一个 JSON 对象。

输出格式（字段名必须完全一致，不要加注释、不要用 Markdown 代码块）：
{{
  "subject": "数学", "subject_detail": "高等数学", "grade": "大学", "image_quality": "清晰",
  "questions": [
    {{"index": 1, "type": "选择题", "stem": "完整题干（含题号、已知条件、要问的问题）",
      "options": ["A. 选项内容", "B. 选项内容"],
      "student_answer": "学生手写的答案，没有手写就填空字符串",
      "student_steps": "学生手写的解题步骤，没有就填空字符串",
      "correct_answer": "你能确定的参考答案，不确定填空字符串",
      "knowledge_points": ["导数", "函数最值"], "difficulty": "中等", "confidence": 0.86}}
  ]
}}

判定规则：
1. subject 只能取：{subjects}；subject_detail 写具体分支…（规则 2、3 与原文件相同，此处省略）
4. 一道题一个元素，按图片中从上到下的顺序编号，最多输出 {max_q} 道题。
5. 看不清的字用 "?" 占位，无法判断的字段填空字符串；**不要编造题目内容**。
6. 不要去判断题目是对是错，也不要在 JSON 里出现任何"对错/状态"字段。

只输出 JSON。"""
```

**② 同步检查这几个地方（不改也能跑，但结果会如表中所示）：**

| 位置 | 不改的后果 |
| --- | --- |
| `pipeline.normalize_question` | 缺 `status` → 归一化成 `unknown`（无需改，这是容错设计） |
| `pipeline.process_image` | `unknown` 会被**强制改成 `blank`** 并打上 `status_guessed` 标记 → **所有题都归到"未做题"目录** |
| `ui/app.py`（自动分析） | 自动错题分析只对 `status == "wrong"` 的题执行 → **不会自动生成错题报告**（仍可手动点「生成/更新分析」） |
| 统计看板 | 错题数会变成 0（因为没有题被判为 wrong） |
| `archive.pattern` / `STATUS_CN` | 目录名仍取"未做题"，无需改 |
| `CLOUD_RECOGNIZE_PROMPT` / `CLOUD_VERIFY_PROMPT` | 如果还开着云端，云端复核会把 `status` 又加回来 → **记得这两个也一并删掉 status**，否则云端结果里又会带状态 |

**③ 改完怎么验证：**

```bat
python tools\modelprobe.py --vision
python tools\verify_recognition.py --only s1 s3
```

`verify_recognition.py` 会打印每题的「题型/状态/置信度/题干」并与标准答案对比（状态列会全部对不上，这是预期的），完整结果在 `samples\recognition_report.json`。

### 10.2 其它常见改法

| 想达到的效果 | 改哪里 | 注意 |
| --- | --- | --- |
| 让"红笔打叉"之外的批注也算错 | `RECOGNIZE_PROMPT` 第 4 条 `wrong` 的描述 | 改完**同步改 `CLOUD_RECOGNIZE_PROMPT`**，否则云端复核口径不一致 |
| 报告要更详细（更多步骤、更多变式题） | `ANALYZE_PROMPT` 的 `solution_steps`、`variants` 要求（例如"给 3 道变式题"） | 云端还要留意 `max_tokens`（默认 4096），写太长会被截断 |
| 报告用更贴合本地教材的知识点写法 | `ANALYZE_PROMPT` 里 `knowledge_points.textbook` 的示例 + `SUBJECT_DETAIL_EXAMPLES` | 纯提示词改动，安全 |
| 增加学科/题型（如"生物""实验题"） | `SUBJECTS` / `QTYPES` | `normalize_subject` 里有别名表，新增学科后建议补别名；归档目录会自动跟着出现 |
| 模型老把"计算题"写成"解答题" | `normalize_qtype` 的映射表 | 比改提示词更省事、更可靠 |
| 完全不想要思考链输出 | 设置里保持勾选「关闭思考链」 | 代码还有兜底：万一答案被写进 `thinking` 而 `content` 为空，会自动取 `thinking` 当正文 |

## 11. 速查卡

**我最常改的 5 件事：**

| 我想要 | 怎么做 |
| --- | --- |
| 识别更快 | 设置 → 本地模型：`送模型最长边` 1600 → **1100**；确认「关闭思考链」已勾选 |
| 识别更准 | `送模型最长边` → 1800~2000；换 `qwen3-vl:8b`（12G+ 显存）；或接云端视觉模型（第 6 章） |
| 少花钱、别出网 | 两种做法任选：① 运行模式选 **「纯本地（完全离线）」** → 识别阶段绝对不调用云端（与开关、Key 无关）；② 关掉顶部「☁ 云端增强」→ `hybrid` / `cloud_first` 下也不调云端。想保留云端分析能力时，Key 留着，只在需要时点「☁ 云端深度分析」 |
| 更深的错题分析 | 填 Key + 勾「启用云端增强」+ `run.cloud_for_analysis = true`，分析走云端；DeepSeek 用 `deepseek-chat`（不勾图片）最省 |
| 一页试卷题数不对 | `单图最多题目数` 调大（如 12~15）；或先在编辑器里裁成两半 |

**一次成功的配置要过这几关：**

| 关卡 | 通过标准 |
| --- | --- |
| ① 本地服务与模型 | `python tools\selfcheck.py` → 「本地模型服务 运行中」；设置 →「刷新模型列表」能看到 `qwen3-vl:4b`，「测试连接」→ 本地模型正常 ✅ |
